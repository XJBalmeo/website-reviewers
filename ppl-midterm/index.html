Lesson 1: Overview of Programming Languages

Lesson 1: Overview of Programming Languages

Core Definitions

What is a Programming Language (PL)?

Core Goal: Studying language principles, design concepts, and implementation effects turns you from a mere user of a programming language into someone who understands how languages work under the hood.
Formal Notation for Computer Execution
A programming language is a formal notation for describing algorithms for execution by a computer.
Provides strict rules so a machine can execute step-by-step instructions without ambiguity.
Convention for Communicating Algorithms
A programming language is a shared convention for communicating algorithms between people and machines.
Allows programmers to read, share, and maintain each other’s logic clearly.
General Notation for Algorithm Description
A programming language is any notation for the description of algorithms.
Focuses on how problem-solving steps are represented symbolically.
Notation for Specifying, Organizing, and Reasoning
Programming languages are notations used for specifying, organizing, and reasoning about computation.
Helps developers structure complex programs and prove that their computations work properly.
Motivation

Six Primary Reasons for Studying Programming Languages

To improve your ability to develop effective algorithms
Understanding a language’s features as a whole increases your capacity to express ideas and maximize the use of the language.
Knowing how language features work helps you design cleaner, smarter problem-solving steps.
To improve your use of existing programming languages
Understanding how features are implemented behind the scenes lets you write much more efficient code.
When you know how memory and control structures work, you avoid slow or wasteful coding habits.
To increase your vocabulary of useful programming constructs
Learning diverse data and control-flow structures keeps you from being limited by the constraints of a single familiar language.
For example, languages like C became popular because they offer rich control-statement implementations for different problems.
To allow a better choice of programming language
Knowing how to evaluate languages helps you pick the right language for the specific application you are building.
Instead of trying to learn every language in existence, you can quickly judge which one fits your project best.
To make it easier to learn a new language
Most languages share the same core concepts (control statements, assignment, and basic data types like integer, real, and character).
Once you master the underlying concepts, learning a new language only requires learning its syntax and unique implementation details.
To make it easier to design a new language
Mastering language design concepts gives you the foundation needed to create your own programming language or domain-specific tool.
Understanding past language trade-offs prevents you from repeating design mistakes.
Language Evaluation

Characteristics of a Good Programming Language

Clarity, Simplicity, and Unity
The language provides a clear conceptual framework so programs are easy to write, read, and decipher when modifications are needed.
Simple and readable syntax lets programmers express ideas directly without confusing workarounds.
Orthogonality
The language has a small set of basic features, each of which is separately understandable and free from unexpected interactions when combined.
High orthogonality means features work consistently together without arbitrary exceptions or side effects.
Naturalness for the Application
Provides appropriate data structures, operations, control structures, and natural syntax suited to the problem domain.
When a language fits the application area naturally, building programs in that field becomes much simpler.
Support for Abstraction
Allows data types, data structures, and operations to be defined and maintained as self-contained abstractions.
Programmers can focus on high-level problem solutions without worrying about low-level implementation details.
Ease of Program Verification (Reliability)
Ensures a program reliably performs its specifications under all circumstances through type checking, exception handling, and aliasing control.
  • Type checking: Verifies compatibility between two variables.
  • Exception handling: Intercepts runtime errors to take corrective measures and continue execution.
  • Aliasing: Having two distinct referencing methods or names pointing to the same memory location.
Programming Environment
Includes a reliable, efficient, and well-documented implementation along with tailored editors, testing packages, and version-control facilities.
Strong development tools speed up writing, debugging, and maintaining large multi-version programs.
Portability of Programs
A language that is compact (few keywords) yet powerful can be moved easily across different hardware and operating systems.
C became famous and widely adopted because its compact design made programs highly portable across machines.
Cost
Evaluates the total financial, time, and hardware expense of adopting a programming language.
Assessed across the six specific cost factors below.
Six Cost Factors in Evaluating a Programming Language
Training the programmer
The time and expense required to teach developers the language’s syntax, rules, and idioms.
Writing programs in the language
The developer effort and time needed to author, structure, and debug source code.
Compiling programs
The computing time and resources needed to translate source code into executable code.
Executing programs
The runtime CPU and memory cost of running the compiled or interpreted program.
Maintenance
The long-term cost of fixing bugs, updating features, and adapting existing code over years of use.
Optimization
The effort required by the compiler or programmer to tune the program for faster speed and lower memory usage.
Operating Context

Effects of Environment on Languages

Host Environment

Development Environment
The environment in which a program is designed, coded, tested, and debugged.
May be a completely different computer system from the one where the finished program runs.

Operating / Target Environment

Execution Environment
The external hardware and software environment that supports the actual execution of a program.
Represents the target machine where the compiled program is ultimately deployed and used.
Four Classes of Programming Environments
Batch Processing Environment
Programs execute from start to finish without live user interaction, processing pre-collected batches of input files.
Requires strong file input/output handling and automated error recovery so a single bad record does not crash the entire batch.
Interactive Environment
Users interact directly with the running program via a terminal or graphical interface.
Requires fast input validation, immediate screen feedback, and graceful handling of user typing errors.
Embedded System Environment
Programs run inside dedicated hardware devices (such as medical equipment, cars, or appliances).
Demands strict real-time speed, low memory usage, direct hardware port access, and high reliability without human intervention.
Programming Environment
An integrated collection of support tools, editors, compilers, debuggers, and libraries used by software teams.
Helps programmers build, test, and combine separate modules into large-scale software systems.
Design Issues

Bindings & The Four Classes of Binding Time

Binding vs. Binding Time: Binding is associating a program element with a specific property (such as a type, value, or memory address). Binding Time is the exact moment when that choice is made.
1. Execution Time (Runtime) & Its Two Sub-Categories
Entry to a Subprogram or Block
Bindings of formal parameters and local variables to storage locations are restricted to occur only upon entering a subprogram or block during execution.
Examples: C and Pascal.
Arbitrary Points During Execution
Bindings of variables to values (via assignment statements) or bindings of names to storage locations that can occur at any point while the program runs.
Examples: LISP and ML permit binding names to storage locations at arbitrary points in the program.
2. Translation Time (Compile Time) & Its Three Sub-Classes
Bindings Chosen by the Programmer
Choices of variable names, variable types, and statement structures written by the programmer in source code.
The translator uses these programmer bindings to determine the final form of the object program.
Bindings Chosen by the Translator
Bindings decided automatically by the language compiler without programmer specification.
Examples include how arrays are laid out in memory and how internal array descriptors are created.
Bindings Chosen by the Loader (Load / Link Time)
The translator assigns relative addresses within each subprogram, while the loader binds variables to actual physical memory addresses before execution.
3. Implementation Time & 4. Definition Time
Implementation Time
Bindings fixed when a specific compiler or interpreter is implemented for a machine (such as the bit width or range of an int).
A program relying on an implementation-time feature may not run on another implementation of the same language, or may run and produce different results.
Definition Time
Bindings fixed permanently when the programming language itself is originally defined.
Includes the language’s fixed keywords, available statement forms, and built-in data structure types.
Paradigms

Six Classes of Programming Paradigms

Imperative Languages (Procedural Languages)
Action-oriented, statement-oriented, or command-driven languages where instructions are executed sequentially step by step.
  • BASIC
  • FORTRAN
  • COBOL
  • PASCAL
Functional Languages
Rooted in the theory of mathematical functions; emphasizes computing values through expressions and functions that can be passed as parameters and returned as results.
  • LISP — List Processing (designed for the IBM 704 by John McCarthy)
  • Scheme — A Lisp dialect
  • ML — Meta Language
  • CLOS — Object-Oriented extension of Lisp
Logic Languages (Rule-Based Languages)
Deals with predicates, facts, and logical relationships rather than step-by-step commands; widely used for Artificial Intelligence (AI).
  • PROLOG — Programming in LOGic
  • OPS5 — Official Production System
  • CLIPS
Object-Oriented Programming (OOP) Languages
Emphasizes the definition of classes and objects, where instances of classes are created dynamically as needed during execution.
  • SmallTalk
  • ADA
  • C++
  • Eiffel
  • Java
Concurrent Languages
Designed for programs that execute in parallel through multiprogramming, multiprocessing, or distributed systems.
  • ALGOL 68
  • Concurrent Pascal
  • CSP
  • ADA
  • Occam
Other Languages (4GL & Specification Languages)
Includes Fourth Generation Languages (4GL) (query languages acting as an interface to a database) and Specification Languages (used for formal hardware and software design).
Focuses on declaring what data or system behavior is needed rather than writing low-level algorithms.

Lesson 2: Describing Syntax and Semantics

Form & Terminology

Programming Language Syntax & Core Terminology

Two Major Components: Every programming language consists of Syntax (the form or structure of valid programs) and Semantics (the meaning of those programs).
Four Definitions of Syntax
Composition of Characters
A set of formal rules that specify the composition of programs from letters, digits, and other characters.
Relationship Independent of Meaning
The relationship among characters or groups of characters, independent of their meaning or the manner of their interpretation and use.
Form of Sentences from Words
A set of rules that define the form of a language—how sentences may be formed as sequences of basic constituents called words.
Well-Formedness Rules
A set of rules that determine whether a sentence is well-formed or not.
Core Syntax Terminology
Sentence
A string of characters over some alphabet.
In a programming language, a valid statement or program is a sentence built from the language’s character set.
Language
A set of valid sentences.
Defines the complete collection of all syntactically legal programs that can be written.
Lexeme
The lowest-level syntactic unit of a language (e.g., *, sum, begin).
Represents the actual character string or word extracted from the source code.
Token
A category of lexemes (e.g., identifier, integer_literal, plus_op).
For example, the lexemes sum, total, and count all belong to the single token category identifier.
Formal Grammars

Recognizers, Generators, Context-Free Grammars & BNF

Recognizers

Recognition Device
Reads input strings over the alphabet of the language and decides whether the input strings belong to the language.
The syntax analyzer (parser) inside a compiler acts as a recognizer.

Generators

Sentence Generator
A device that generates valid sentences of a language.
You can check if a sentence is syntactically correct by comparing it to the structure of the generator.
Context-Free Grammars (CFG)
Developed by Noam Chomsky in the mid-1950s as language generators meant to describe the syntax of natural languages.
They define the class of languages known as context-free languages.
Backus-Naur Form (BNF, 1959)
Invented by John Backus to describe the syntax of Algol 58; BNF is mathematically equivalent to context-free grammars.
Became the universal metalanguage for specifying programming language syntax.
Nonterminals (Abstractions) vs. Terminals
Nonterminals are syntactic variables enclosed in angle brackets (e.g., <stmt>), while Terminals are the actual lexemes or tokens of the language.
A BNF rule has a Left-Hand Side (LHS) (a nonterminal) and a Right-Hand Side (RHS) (a string of terminals and/or nonterminals).
<ident_list> → identifier | identifier, <ident_list> <if_stmt> → if <logic_expr> then <stmt>
Grammar and Start Symbol
A Grammar is a finite, non-empty set of rules, and the Start Symbol is the special top-level nonterminal from which all derivations begin.
For example, <program> typically serves as the start symbol for an entire program grammar.
Derivations & Trees

Derivations, Sentential Forms & Parse Trees

Sentential Form vs. Sentence
Every string of symbols at any step in a derivation is a sentential form; a sentence is a sentential form that has only terminal symbols.
Once all angle-bracket nonterminals have been replaced by actual tokens, the derivation is complete.
Leftmost Derivation
A derivation in which the leftmost nonterminal in each sentential form is always the one expanded next.
Note that a general derivation may be leftmost, rightmost, or neither leftmost nor rightmost.
Worked Example: Grammar & Leftmost Derivation of a = b + const
Starting from <program>, we replace the leftmost nonterminal step by step until only terminals remain:
// Example Grammar: <program> → <stmts> <stmts> → <stmt> | <stmt> ; <stmts> <stmt> → <var> = <expr> <var> → a | b | c | d <expr> → <term> + <term> | <term> - <term> <term> → <var> | const // Leftmost Derivation of "a = b + const": <program> => <stmts> => <stmt> => <var> = <expr> => a = <expr> => a = <term> + <term> => a = <var> + <term> => a = b + <term> => a = b + const
Parse Tree
A hierarchical tree representation of a derivation, where internal nodes are nonterminals and leaf nodes are terminals.
Grammar Ambiguity

Ambiguity in Grammars

What is an Ambiguous Grammar?
A grammar is ambiguous if and only if it generates a sentential form that has two or more distinct parse trees.
Ambiguity is a problem for compilers because two different parse trees can change the order of operations and produce different meanings.
// Ambiguous Grammar Example: <expr> → <expr> <op> <expr> | const <op> → / | -

Tree 1: Groups (const - const) / const

Tree 2: Groups const - (const / const)

Rules, Criteria & Elements

Lexical vs. Syntactic Rules, 5 Criteria & 11 Syntactic Elements

Lexical Rules vs. Syntactic Rules
Lexical rules define the character alphabet and how characters combine into valid words (tokens), while Syntactic rules define how words combine into valid sentences (statements).
  • Pascal: Uses <> for not equal.
  • C: Uses != for not equal (<> is not valid).
  • Ada: Uses /= for not equal, while <> stands for an undefined range of an array index.
Five Syntactic Criteria
Readability
How easily a program’s logic and structure can be read and understood by a programmer.
Writability
How easily and concisely a programmer can express computations in code.
Ease of Verifiability
How easily a program can be tested and proven correct against its specification.
Ease of Translation
How simply and efficiently a compiler can parse and translate the source code into machine code.
Lack of Ambiguity
Ensures every valid statement has one and only one syntactic interpretation.
Eleven Syntactic Elements of a Language
Character Set
The approved alphabet of letters, digits, and symbols (such as ASCII or Unicode) used to write source text.
Identifiers
Programmer-chosen names for variables, functions, and types.
Operation Symbols
Characters or symbol pairs representing arithmetic, relational, or logical operations (e.g., +, *, !=).
Keywords and Reserved Words
Words with special grammatical meaning in the language (such as if, while, int).
Noise Words
Optional words that can be inserted into statements purely to improve human readability (such as optional THEN in COBOL).
Comments
Non-executable explanatory notes ignored by the compiler and written for human maintainers.
Blanks (Spaces)
Whitespace characters used to separate adjacent tokens.
Delimiters and Brackets
Punctuation and grouping markers that mark the boundaries of statements or blocks (e.g., ;, { }, ( ), begin...end).
Free- and Fixed-Field Formats
Rules governing whether statements can be written anywhere on a line (free-field) or must sit in specific character columns (fixed-field).
Expressions
Combinations of operands and operators that are evaluated to produce a value.
Statements
Complete syntactic sentences that command the computer to perform an action (such as assignment, branching, or looping).
Semantics & Translation

Semantics & Stages in Compiler Translation

Semantics (Axiomatic & Denotational)
Defines the meaning of any syntactically valid program written in the language.
  • Axiomatic Semantics: Specifies meaning using logical assertions (pre-conditions and post-conditions).
  • Denotational Semantics: Specifies meaning by mapping language constructs to mathematical objects.
Formal Translation Models
Uses Syntax Diagrams and Extended Backus-Naur Form (EBNF) as the standard formal models for syntax description.
Structure of a Compiler (Stages in Translation Diagram)
Pass 1: Analysis of the Source Program (Source Program Recognition Phase)
Lexical Analysis (Scanner)
Reads the raw source text character by character, identifies statement components, and outputs Lexical Tokens.
Syntactical Analysis (Parser)
Checks the token stream to ensure all grammar rules of the language are followed and builds a Parse Tree.
Semantic Analysis (Central Bridge)
Acts as the central bridge between the Analysis and Synthesis parts of translation, producing Intermediate Code.
  • Symbol-table maintenance: Relates symbolic addresses (variable names) to absolute machine addresses.
  • Most error detection: Catches type and semantic errors.
  • Expansion of macros: Expands macro definitions inline.
  • Execution of compile-time statements: Evaluates compile-time directives.
Pass 2: Synthesis of the Object Program (Object Code Generation Phase)
Optimization
Manipulates and refines the intermediate code into Optimized Intermediate Code so the program runs faster or uses less memory.
Code Generation
Translates the optimized intermediate representation and symbol-table data into machine or assembly Object Code.
Linking
Combines the generated object code with object code from other compilations/libraries to produce the final Executable Program.

Lesson 3: Names, Bindings, Type Checking, and Scopes

Architecture & Names

Von Neumann Architecture & Variable Naming Issues

Hardware Foundation: Imperative programming languages are abstractions of the von Neumann architecture, which consists of Memory, Processor (CPU), and Peripherals.
Four Design Issues for Naming Variables
Length
Determines how many characters are allowed in an identifier name.
Older languages limited names to 6–8 characters, while modern languages allow long descriptive names.
Special Characters
Specifies which non-alphanumeric symbols (such as underscores _, hyphens -, or sigils $) are permitted in names.
Case Sensitivity
Decides whether uppercase and lowercase letters are treated as distinct identifiers (e.g., rose vs. Rose vs. ROSE).
C-based languages are case-sensitive, which can hurt readability when similar names differ only by capitalization.
Special Words (Keywords vs. Reserved Words)
A keyword is special only in certain contexts and can be redefined by the programmer, whereas a reserved word cannot be used as a programmer-defined name anywhere.
Reserved words make programs much easier to read and prevent confusing name clashes.
Variable Attributes

Variables as a Sextuple of Six Attributes

What is a Variable? A variable is an abstraction of a computer memory cell (or collection of cells) characterized by six core attributes.
Name
The identifier string used to refer to the variable in source code.
Not all variables have names—anonymous heap-dynamic variables accessed via pointers have no name.
Address (L-Value)
The physical memory address with which the variable is associated.
Called the l-value because a variable’s address is what is required when it appears on the left side of an assignment.
Value (R-Value)
The contents stored inside the memory location associated with the variable.
Called the r-value because a variable’s value is what is read when it appears on the right side of an assignment.
Type
Determines the range of values the variable can store and the set of operations defined for values of that type.
In the case of floating-point numbers, the type also determines the precision of the value.
Lifetime
The time interval during program execution when the variable is bound to a specific memory location.
Begins when storage is allocated and ends when that storage is deallocated.
Scope
The range of program statements over which the variable is visible and can be referenced.
Determines which parts of the program are allowed to read or modify the variable by name.
Storage Lifetimes

Four Categories of Variables by Lifetimes

Static Variables
Bound to memory cells before execution begins and remain bound to the same memory cell throughout execution.
Fastest access because there is no runtime overhead for allocating or deallocating memory, though it prevents recursion.
Stack-Dynamic Variables
Storage bindings are created on the runtime stack when their declaration statements are elaborated (when the function is called).
For scalar stack-dynamic variables, all attributes except the memory address are statically bound at compile time; supports recursive functions.
Explicit Heap-Dynamic Variables
Nameless memory cells allocated and deallocated from the heap by explicit programmer directives during execution (such as new / delete or malloc / free).
Can only be referenced indirectly through pointer or reference variables; used to build dynamic structures like linked lists and trees.
Implicit Heap-Dynamic Variables
Bound to heap storage automatically whenever a value is assigned to the variable through an assignment statement.
All attributes (type, size, and address) are bound dynamically at assignment time, offering maximum flexibility at the cost of runtime overhead.
Scoping Rules

Scope: Static Scoping, Global Scoping & Dynamic Scoping

Local, Nonlocal, and Global Variables
Local variables are declared inside a program unit; Nonlocal variables are visible inside the unit but not declared there; Global variables are a special category of nonlocal variables declared outside all functions.
Static Scoping (Spatial / Lexical Scope)
Introduced in Algol 60; binds variable references at compile time by searching declarations locally first, then outward through enclosing static scopes.
Enclosing scopes are called static ancestors, and the nearest enclosing scope is the static parent. Nested static scopes are supported in Ada, JavaScript, Common LISP, Scheme, Fortran 2003+, F#, and Python.
Global Scoping & Declarations vs. Definitions (C and C++)
Languages like C, C++, PHP, and Python allow variables to be declared outside function definitions.
In C and C++, a declaration specifies only attributes (e.g., extern int x; means it is defined in another file), whereas a definition specifies attributes and allocates storage.
Dynamic Scoping (Temporal / Call-Chain Scope)
Based on the runtime calling sequence of subprograms rather than their spatial layout in source code; resolves names by searching backward through the chain of active function calls.
  • Advantage: Convenience (shared variables do not need to be passed as explicit parameters).
  • Disadvantage 1: While a subprogram executes, its local variables are visible to all subprograms it calls.
  • Disadvantage 2: Impossible to statically type-check variable references at compile time.
  • Disadvantage 3: Poor readability because a variable’s type and declaration cannot be determined statically.
Scope vs. Lifetime
Scope is spatial (where in the code a name is visible), while Lifetime is temporal (how long the memory cell exists during execution).
Example: A static variable declared inside a C or C++ function has local scope (visible only inside that function), but static lifetime (keeps its value in memory across the entire program run).
Environments & Constants

Referencing Environments & Named Constants

Referencing Environment
The collection of all names that are visible in a given statement.
In a static-scoped language, it consists of the local variables plus all visible variables in enclosing scopes. In a dynamic-scoped language, it consists of the local variables plus all visible variables in all currently active subprograms (subprograms whose execution has begun but not yet terminated).
Named Constants (Static vs. Dynamic Binding)
A variable that is bound to a value only once when it is bound to storage; improves readability, modifiability, and program parameterization.
Values can be bound statically at compile time (called manifest constants) or dynamically at runtime using expressions (supported in Ada, C++, and Java).
C# Named Constants: const vs. readonly
C# provides two distinct kinds of named constants depending on binding time:
  • const: Values are bound statically at compile time.
  • readonly: Values are dynamically bound at runtime (can be set inside a constructor).

Lesson 4: Data Types

Numeric Primitives

Elementary Data Types: Numeric Types & Operations

Elementary (Primitive) Data Types: Basic built-in data types that are not built from other types—most commonly Numeric (Integer & Real), Boolean, and Character.
Integer Data Type
Whole numbers with or without a sign forming a finite ordered subset of mathematical integers supported directly by hardware.
Supports arithmetic operations, relational operations, assignment operations, and bit operations.
Unary, Binary & Ternary Arithmetic Operations
Operations classified by how many operands they take:
  • Unary Operation (integer → integer): Takes 1 operand, such as negation (-), identity (+), or increment (++I in C).
  • Binary Operation (integer × integer → integer): Takes 2 operands: addition (+), subtraction (-), multiplication (*), division (/), integer quotient (DIV), and remainder (MOD).
  • Ternary Operation (Pr1 ? opr2 : opr3): Conditional shorthand for if...else in C/Java; returns opr2 if Pr1 is true, or opr3 if Pr1 is false.
Relational Operations (integer × integer → Boolean)
Compares two argument values (equal, less than, greater than, not equal, less-than-or-equal, greater-than-or-equal) and returns a Boolean (True or False) result.
Real Numbers (Floating-Point)
Numbers containing a decimal point with or without a sign (e.g., 1.25, +1.25, -1.25).
Called real in Fortran and Pascal, and called float in C and C++.
Complex Numbers
An ordered pair of real numbers expressed in the form a + bi (where i2 = -1), representing a real part and an imaginary part.
Stored in memory as a block of two contiguous storage locations containing the real and imaginary values.
Rational Numbers
Represented as the exact quotient of two integers (a / b).
Its main advantage is avoiding the round-off and truncation errors encountered in floating-point and fixed-point representations of real numbers.
Logical & Character Types

Booleans & Character Data Types

Boolean Data Type & Five Logical Operations
A data object that holds a true or false value and supports assignment plus five logical operations: Conjunction (and), Inclusive Disjunction (or), Negation Complement (not), Implication (imp), and Equivalence (equiv).
r and j = if r then j else false // Conjunction j or r = if j then true else r // Inclusive Disjunction not k = if k then false else true // Negation Complement x imp y = if x then y else true // Implication r equiv j = if r then j else not j // Equivalence
Boolean Representations Across Languages
Different languages implement Booleans in distinct ways:
  • ALGOL 60: Represents Booleans with literals true and false and does not allow mixing them with numeric values.
  • Pascal & Ada: Views Boolean as a predefined ordered enumerated type (FALSE < TRUE) that may be redefined by the programmer.
  • PL/I: False is any string containing all zeros or the empty string, while True is any string containing at least one non-zero character.
Character Data Type
A data object holding a single character (such as 'B', 'K', or 'g') mapped to a hardware/OS character encoding like ASCII.
Supports relational comparisons, assignment, and testing whether a character is a letter, digit, or special character.
Homogeneous Structures

Structured Data Types: Vectors, Arrays & Matrices

Structured Data Type: A data object composed of more than one element (containing other data objects as its components), including Vectors & Arrays, Records, Lists, Character Strings, and Pointers.
Vector (One-Dimensional / Linear Array)
A data structure composed of a fixed number of components of the same data type (homogeneous) organized as a simple linear segment.
PASCAL: v : array[1..10] of integer; FORTRAN: DIMENSION A(10) C: int j[10];
Three Attributes of an Array
Number of Components
The total number of elements is implicitly indicated by the array’s subscript range.
Single Homogeneous Data Type
One data type is specified for all components; every element in the array must share that exact same type.
Subscript Selection
An index or subscript is used to select each individual component.
Four Operations on Arrays
Subscripting
Selects a specific component from a vector and returns its l-value (memory location).
Create and Destroy Vectors
Allocates and deallocates memory storage for the array components.
Assignment to a Component
Stores a new value into a selected element of the vector.
Arithmetic Operations
Performs mathematical operations across array elements or whole vectors.
Multidimensional Arrays (Matrix Storage Order & Language Differences)
Row-Major Order
Divides the matrix into a vector of row sub-vectors; stores Row 1 completely in contiguous memory, followed by Row 2.
Column-Major Order
Treats the matrix as a sequence of columns; stores Column 1 completely in contiguous memory, followed by Column 2 (used in FORTRAN).
Array Slicing & Language Differences
An array slice is a subordinate part of an array that is itself an array (supported in PL/I and FORTRAN).
Languages also differ in their indexing syntax, allowed component types, compile-time vs. run-time bounds, array initialization rules, and built-in array operations.
Heterogeneous Structures

Records (Structures)

What is a Record (Structure)?
A data structure composed of a fixed number of components of different data types (heterogeneous), where fields are named with symbolic identifiers rather than indexed with subscripts.
Called a record in Pascal and Ada, and called a struct (structure) in C and C++.
Three Attributes & Two Operations of a Record
Defined by 3 Attributes (Number of components, Data type of each component, and Selector name for each component) and 2 Operations:
  • Attribute 1: Number of components.
  • Attribute 2: Data type of each component.
  • Attribute 3: Selector used to name every component.
  • Operation 1 (Component Selection): Accessing fields via dot notation (e.g., Student.SNO in C, Pascal, and Ada).
  • Operation 2 (Assignment): Assigning an entire record to another record of identical structure.
// C Structure Declaration & Selection: struct StudentType { int SNO; char Name; int Age; float Tuitionfee; char Dept; } Student; Student.SNO = 12345; // Pascal Record Declaration & Selection: Type Studentype = Record SNO: array [1..8] of integer; Name: array [1..30] of char; Age: integer; End; var student: studentype; Student.SNO := 12345; Student.Name := "Kyra";
Lists & Strings

Lists & Character Strings

Lists vs. Arrays (Three Key Differences)
A List is an ordered sequence of items or data structures (central to LISP) that differs from an array in three ways:
  • 1. Length: Arrays have fixed length, while lists are rarely of fixed length.
  • 2. Homogeneity: Array components must share a single data type, while list items may differ in data type from their neighbors.
  • 3. Declaration: Languages that use lists (like LISP) declare list data implicitly without explicit member declarations.
Three Variations of Lists
Specialized list structures used across computer science include:
  • 1. Stacks and Queues
  • 2. Trees
  • 3. Directed Graphs
Character Strings & Three Length Treatments
A data object composed of a sequence of characters, handled by languages in one of three ways:
  • 1. Fixed Declared Length: Static character length fixed at compile time.
  • 2. Variable Length to a Declared Bound: Dynamic length up to a declared maximum limit.
  • 3. Unbounded Length: Fully dynamic length with no preset bound.
Four Operations on Character Strings & SNOBOL
Character strings support four core operations:
  • 1. Concatenation: Joining two strings together.
  • 2. Relational operation: Comparing strings lexicographically.
  • 3. Substring selection: Positioning substrings and pattern matching.
  • 4. Formatting for input-output: Structuring text for display or file storage.
The SNOBOL language was built specifically for string processing: its concatenation operator is implicit, and its most fundamental statement is the pattern matching statement.
Indirect Referencing

Pointers: Problems, Operations & Language Notations

What is a Pointer?
An identifier whose value is a reference (memory address) to some object, popularized by Pascal, C, and Ada.
Solves the problem of dynamically producing and linking an undetermined number of data items without explicitly naming every object.
Three Classic Problems with Pointers
Using pointers introduces three well-known hazards:
  • 1. Aliasing: Several pointer variables pointing to the same object simultaneously.
  • 2. Unreferenced Objects (Garbage): Objects that are no longer pointed at by any pointer variable.
  • 3. Location vs. Value Distinction: Ambiguity when a variable denotes either a memory location or a value.
Three Operations on Pointers
Pointers support three fundamental operations:
  • 1. Assignment: Setting a pointer variable to hold an object’s memory address.
  • 2. Equality: Comparing whether two pointers reference the same location.
  • 3. Dereferencing: Following the pointer to access or modify the target object’s value.
Language Pointer Assignment (Copy Address) Value Assignment (Dereference & Copy Value) Field Selection via Pointer
ALGOL 68 p := q T(p) := q field of p
PASCAL p := q P↑ := q↑ p↑.field
ADA p := q p.all := q.all p.field

Lesson 5: Sequence Control

Execution Order

Sequence Control vs. Data Control & Implicit vs. Explicit Control

Sequence Control

Order of Execution
Controls the order in which operations and statements are executed in a program.
  • a. Expressions: Controlling the order of operations inside formulas.
  • b. Between statements or groups of statements: Controlling branching, looping, and compound blocks.
  • c. Between subprograms: Controlling function calls and returns.

Data Control

Transmission of Data
Controls how data is provided to operations and transmitted among subprograms of a program.
Covers variable scoping, referencing environments, and parameter passing (covered in Unit 6).
Implicit Sequence Control Structure
The default execution order defined automatically by the language unless modified by the programmer.
Examples include executing statements sequentially from top to bottom and following built-in operator precedence rules (like multiplying before adding).
Explicit Sequence Control Structure
Control structures written optionally by the programmer to override or modify the language’s implicit sequence.
Examples include placing parentheses in an expression, or writing if, while, goto, and break statements.
Arithmetic Expressions

Sequencing with Arithmetic Expressions: Trees & Notations

High-Level Expressions vs. Machine Instructions
A mathematical formula like A = (B + D) / K requires at least 6 separate instructions in machine or assembly language, but can be written in a single parenthesized line in a high-level language like C.
Proper parentheses give the programmer explicit sequence control over the order of operations inside the expression.
Functional Composition (Expression Tree)
The basic sequence-control mechanism inside an expression is functional composition, which gives an expression the structure of a tree.
The root node represents the main (final) operation, intermediate nodes represent intermediate operations, and leaf nodes represent the operands.
Prefix (Polish Prefix) Notation
The operation symbol is written first, followed by the operands in order from left to right.
+ a b // Adds a and b
Postfix (Suffix / Reverse Polish) Notation
The reverse of prefix: the operands are written first, followed by the operation symbol.
a b * // Multiplies a and b
Infix Notation
The operation symbol is written between the two operands; this is the everyday notation used for binary arithmetic, relational, and logical operations in most programming languages.
Note that languages like C and Java also use prefix and postfix unary operators (++x and x++) to increment or decrement values.
a * b // Multiplies a and b
Non-Arithmetic Sequencing

Sequencing with Non-Arithmetic Expressions

Pattern Matching & Term Rewriting
An operation that succeeds by matching and assigning a set of variables to a predefined template.
Recognizing parse trees in BNF is a form of pattern matching. A restricted form called Term Rewriting is used in languages like ML to define functions and generate derivations.
Unification
The substitution of variables in relations during pattern matching to determine whether a query has a valid substitution consistent with the rules and facts in a database.
PROLOG relies on unification as its core mechanism for answering logical queries.
Backtracking
An algorithm that tries all possible matches searching for success by successively stacking and unstacking partial results whenever a path fails.
Works hand-in-hand with unification in logic languages to explore alternative rules in the database automatically.
Statement-Level Control

Sequence Control Between Statements

I. Basic Statements
Assignment to Data Objects (L-Value vs. R-Value)
The central operation for elementary data types, which assigns the r-value (data object value) of an expression to the L-value (memory location) of the target variable.
A = B + C // A -> L-value (target memory location where result is stored) // B + C -> r-value (evaluated data object value)
Input Statement & Other Assigning Operations
Input statements read data from the screen (CRT), files, or communication lines into variables, while other assigning operations include parameter transmission (assigning argument values to formal parameters).
Three Forms of Statement-Level Sequence Control & Explicit Jumps
Composition, Alternation, and Iteration
Statement-level sequence control takes three fundamental forms:
  • 1. Composition: Executing statements in sequential order.
  • 2. Alternation: Choosing between alternative statements based on a condition.
  • 3. Iteration: Repeating a statement or block multiple times.
Explicit Sequence Control: Goto & Break Statements
Direct jump statements that transfer execution control explicitly:
  • 1. Goto Statement: Transfers control to another statement via either Unconditional goto (always jumps) or Conditional goto (jumps if a condition is satisfied).
  • 2. Break Statement: Causes control to move forward to an explicit point at the end of a given control structure.
II. Structured Sequence Control (Structured Programming)
Compound Statement
A sequence of statements treated as a single statement (such as begin...end or { ... }).
Implemented by placing blocks of executable code representing each constituent statement sequentially in memory.
Conditional Statement (If & Case Statements)
Expresses alternation of statements controlled by a condition expression.
  • 1. If statements
  • 2. Case statements
Iteration Statements (Head & Body)
Provides the basic mechanism for repeated calculation and consists of two parts: the Head (controls how many times the loop runs) and the Body (the statement or compound statement executed repeatedly).
  • 1. While ..., do
  • 2. For ... until ...
  • 3. Loop ... end loop
  • 4. Do while ... end while
  • 5. Do while do ... end do while do

Lesson 6: Subprogram Control

Call-Return Structure

Subprogram Sequence Control & Simple Call-Return

Simple Subprogram Call-Return: A program has one main program that calls subprograms. When a subprogram calls another subprogram, the caller’s execution is halted, the called subprogram executes to completion, and control returns to the caller.
Five Characteristics of an Efficient Simple Subprogram
It must not be recursive
The subprogram cannot call itself directly or indirectly, allowing activation records to be allocated statically without stack overhead.
There is an explicit call statement
Subprograms are invoked through a clear, explicit call instruction in the code.
Subprogram must be executed completely for every call
Each invocation starts at the beginning and runs all the way to termination before returning (unlike coroutines that pause and resume mid-execution).
Immediate transfer of control at point of call
As soon as the call statement is reached, execution jumps immediately into the called subprogram.
Single execution sequence
Only one program unit is actively executing at any given moment in a single thread of control.
Data Control & Naming

Attributes of Data Control, Names & Referencing Environments

Attributes of Data Control
Determines how data is provided for each operation and how the result of an operation is saved and retrieved for future use as an operand.
For example, in A = B * 2 - Y, data control determines which specific memory cells the identifiers A, B, and Y refer to during that execution.
Two Ways a Data Object is Made Available as an Operand
Operands reach an operation through either Direct Transmission or Referencing Through a Named Data Object:
  • 1. Direct Transmission: The data object is allocated temporary storage during its lifetime and is never given a name.
  • 2. Referencing Through a Named Data Object: The data object is accessed by its identifier name for data control during execution.
Nine Program Elements That May Be Named
Variable
Named memory cell holding a modifiable data value.
Formal parameter
Named local data object in a subprogram header that receives an argument from the caller.
Subprogram
Named procedure, function, or method that can be invoked by other code.
Defined Types
Programmer-defined data type names (such as a struct or record type).
Defined Constant
Symbolic name bound permanently to a fixed value.
Statement
Statement labels used as targets for jumps or loop exits.
Execution
Named tasks, threads, or coroutines representing an active execution sequence.
Primitive Operations
Built-in operator symbols or intrinsic function names (such as + or sin).
Literal constants
Self-naming constant tokens written directly in code (such as 2, 3.14, or true).
Four Components of Referencing Environments
Local Referencing Environment (Local Environment)
Identifier associations (formal parameters, local variables, and local subprograms) created upon entry to the subprogram and visible only inside it.
Non-Local Referencing Environment
Identifier associations visible inside the subprogram that were not created on its entry (resolved via static enclosing scopes or dynamic call chains).
Global Referencing Environment
A special part of the non-local environment containing associations created at the start of the main program and visible across subprograms.
Predefined Referencing Environment
Identifier associations defined directly in the language specification (built-in types, constants, and standard operations) available to all programs.
Four Basic Approaches to Shared Data in Subprograms (Non-Local Environment)
Explicit Common Environment & Implicit Non-Local Environment
Sharing data objects through explicitly declared shared data blocks (like Fortran COMMON or extern globals) or default global visibility.
Dynamic Scope
Resolving non-local names by searching the active runtime chain of calling subprograms.
Static Scope
Resolving non-local names at compile time through enclosing lexical program units.
Inheritance
Sharing data attributes and operations across parent and child classes in object-oriented hierarchies.
Parameter Passing

Parameters & Five Methods for Transmitting Parameters

Formal Parameter

Subprogram Heading Parameter
A local data object declared inside the subprogram heading (e.g., R and J in SUB(int R, char J)).
Acts as the placeholder name used inside the subprogram body.

Actual Parameter (Argument)

Caller-Provided Data Object
The data object shared by the caller subprogram when invoking the subprogram.
Can be a local variable of the caller, a formal parameter of the caller, a visible non-local variable, or a result returned by a function.
Five Methods for Transmitting Parameters
Call by Name
Views a subprogram call as a textual substitution for the entire body of the subprogram, where every formal parameter is replaced by the actual parameter expression.
Each time the formal parameter is referenced during execution, the corresponding actual parameter expression is re-evaluated from scratch.
Call by Reference
Passes a pointer (memory address) to the location of the actual data object to the subprogram; the data itself does not change position in memory.
Any modification made to the formal parameter inside the called subprogram immediately updates the caller’s original variable via two-stage pointer addressing.
Call by Value-Result (Copy-In / Copy-Out)
The formal parameter is a local variable of the same data type initialized with the actual parameter’s value on entry, and its final value is copied back to the actual parameter upon termination.
While the subprogram is running, the caller’s actual parameter retains its original value until the subprogram finishes.
Call by Constant Value
Transmits the parameter as a read-only constant so no change in the value of the formal parameter is allowed during execution.
Protects the parameter from accidental modification inside the subprogram.
Call by Result (Out-Only Parameter)
Used solely to transmit a final result back out to the caller at the end of the subprogram.
The initial value of the actual parameter is ignored and cannot be read inside the subprogram; when the subprogram terminates, the formal parameter’s final value is assigned to the actual parameter.
Data Abstraction

Abstract Data Types (ADT), Information Hiding & Subprogram Specs

Abstract Data Type (ADT) & Encapsulation
Defined as a set of data objects and a set of abstract operations on those data objects, encapsulated together so data can only be manipulated through the defined operations.
Encapsulation simplifies programs and lets developers replace the internal data representation without breaking outside code.
Modularity vs. Abstraction
Two complementary solutions for managing large programs of thousands of lines:
Modularity allows us to design and build a program from smaller pieces called modules, whereas Abstraction allows us to understand and analyze a problem by concentrating on its important aspects and ignoring irrelevant details.
Information Hiding & Its Two Benefits
Hides the underlying low-level bit-string representation of a data type so programmers can only modify values by applying high-level operations.
  • 1. Programming style: Promotes cleaner, safer, and more structured code.
  • 2. Modifiability: Allows internal data representations to change without rewriting the rest of the program.
Encapsulation by Subprogram & Three Specification Parts
Viewed at both the Program design level and Language design level, every subprogram specification consists of three parts:
  • 1. Name of the subprogram
  • 2. Prototype (Signature) of the subprogram: Gives the number of arguments, their data types, number of results, and their order.
  • 3. Action performed by the subprogram
int Addition(int X, int Y); // Returns an integer result void sub(float K, int Y); // Returns a null (void) function
Hidden Call/Return Actions (Activation Record & Epilogue)
When a subprogram is called, the translator inserts hidden setup instructions before execution to create the activation record, set up non-local referencing, and transmit parameters.
Upon termination, the translator inserts an epilogue (a block of cleanup instructions at the end of the subprogram) to return results and free the storage for the activation record.
Type Definitions & Type Equivalence
A Type Definition binds a type name to a declaration describing the structure of a class of data objects, so variables (`S1, S2, S3`) can be declared using the type name without repeating the structure definition.
  • 1. Type Equality: What it means to say that two types are the same.
  • 2. Data Object Equality: What it means to say that two data objects of the same type are equal.
// PASCAL Type Definition: type Student = record studio : integer; lastname : array of char; firstname : array of char; course : array of char; end; var S1, S2, S3 : Student; // C Struct Type Definition: struct student { int studio; char lastname[25]; char firstname[25]; char course[10]; }; struct student S1, S2, S3;
