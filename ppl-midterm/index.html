Lesson 2 • Step 1 of 7 • Form vs. Meaning

Syntax Definitions & Fundamental Terminology

Two Major Components of Every PL: Syntax defines the form/structure of valid programs, while Semantics defines the meaning of those programs.
1
Ghezzi (Composition): Formal rules specifying the composition of programs from letters, digits, and other characters.
2
Rosenberg (Structure vs. Meaning): Relationship among characters or groups of characters, independent of their meaning or manner of interpretation and use.
3
Ghezzi (Word Sequences): Rules defining how sentences may be formed as sequences of basic constituents called words.
4
Horowitz (Well-Formedness): Rules determining whether a sentence is well-formed or not.

4 Core Syntax Terms (Sebesta Hierarchy):

1. LANGUAGE: A set of valid sentences.
2. SENTENCE: A string of characters over some alphabet.
3. TOKEN: A category of lexemes (e.g., identifier, operator).
4. LEXEME: The lowest-level syntactic unit of a language (e.g., *, sum, begin).

Lesson 2 • Step 2 of 7 • Formal Grammars

Recognizers vs. Generators, Context-Free Grammars & BNF

Recognizers (Syntax Checkers)

R
Reads input strings over the alphabet of the language and decides whether the input strings belong to the language (used in compiler parsers).

Generators (Sentence Producers)

G
A device that generates valid sentences of a language. Syntax correctness is determined by comparing a sentence to the generator's structure.
CFG
Context-Free Grammars (Noam Chomsky, mid-1950s): Language generators developed to describe natural language syntax; define the class of context-free languages.
BNF
Backus-Naur Form (John Backus, 1959): Invented to describe the syntax of Algol 58; mathematically equivalent to context-free grammars.
LHS
Nonterminals (Syntactic Variables / Abstractions): Enclosed in angle brackets (e.g., <if_stmt>); appear on the Left-Hand Side (LHS) of a rule.
RHS
Terminals & Rules: Terminals are actual lexemes/tokens. A rule's Right-Hand Side (RHS) is a string of terminals and/or nonterminals.
S
Grammar & Start Symbol: A Grammar is a finite, non-empty set of rules; the Start Symbol is the special top-level nonterminal (e.g., <program>).
// Classic BNF Rule Examples (Recursive list & Selection statement): <ident_list> → identifier | identifier, <ident_list> <if_stmt> → if <logic_expr> then <stmt>

Lesson 2 • Step 5 of 7 • External Appearance

Lexical vs. Syntactic Rules, 5 Criteria & 11 Syntactic Elements

Lex
Lexical Rules: Define the set of characters constituting the language's alphabet and how characters combine to form valid words.
Syn
Syntactic Rules: Define how words/tokens combine to form valid sentences and statements.
Ex
Cross-Language "Not Equal" Operator Comparison:
• Pascal: Uses <> for not equal.
• C: <> is invalid; uses != for not equal.
• Ada: Uses /= for not equal, while <> stands for an undefined range of an array index.
5 Syntactic Design Criteria
1
Readability: Ease with which programs can be read and understood.
2
Writability: Ease of creating programs in the language.
3
Ease of Verifiability: Supporting correctness proofs and testing.
4
Ease of Translation: Simplicity of parsing and compiling source code.
5
Lack of Ambiguity: Every construct has exactly one syntactic interpretation.
11 Syntactic Elements of a Programming Language (Pratt)
1
Character Set: Underlying alphabet (e.g., ASCII).
2
Identifiers: Programmer-chosen names for variables, functions, and types.
3
Operation Symbols: Arithmetic, relational, and logical operators (+, *, !=).
4
Keywords and Reserved Words: Special control/type words (if, while, int).
5
Noise Words: Optional words inserted to improve readability (e.g., optional THEN).
6
Comments: Non-executable documentation notes for human readers.
7
Blanks (Spaces): Whitespace rules separating tokens.
8
Delimiters and Brackets: Syntactic markers (;, { }, ( ), begin...end).
9
Free- and Fixed-Field Formats: Column-sensitive vs. free-form statement layout.
10
Expressions: Combinations of operands and operators computing a value.
11
Statements: Complete executable sentences commanding an action.

Lesson 2 • Step 6 of 7 • Meaning & Translation

Semantics & The Two-Pass Compiler Architecture

Sem
Semantics: Defines the meaning of any syntactically valid program. Formally specified in two ways:
1. Axiomatic Semantics (logical assertions/pre- and post-conditions)
2. Denotational Semantics (mapping language constructs to mathematical objects)
Mod
Formal Translation Models: Syntax diagrams and Extended Backus-Naur Form (EBNF) are the standard for formal syntax description.

Compiler Two-Part Translation Pipeline (Connected to the Symbol Table):

Part 1: Analysis (Source Recognition / Pass 1)

1
Source Program (Text) → Lexical Analysis (Scanner): Identifies statement components and outputs Lexical Tokens.
2
Syntactic Analysis (Parser): Verifies grammar rules and builds the Parse Tree.
3
Semantic Analysis (Central Bridge): Bridges Analysis & Synthesis; outputs Intermediate Code.

Part 2: Synthesis (Object Code Generation / Pass 2)

4
Optimization: Manipulates intermediate code into Optimized Intermediate Code.
5
Code Generation: Produces Object Code from collected symbol & intermediate data.
6
Linking: Combines object code with Object Code from Other Compilations to output final Executable Code.
The Symbol Table Hub: Created by the compiler or assembler to relate symbolic addresses (variable names) to absolute machine addresses. It interacts directly with Lexical Analysis, Syntactic Analysis, Semantic Analysis, Optimization, and Code Generation.

Categories of Variables by Lifetimes

1

Lesson 3 • Step 4 of 6 • Visibility Rules

Local vs. Nonlocal Variables, Static Scoping & Global Scoping

Local Variables

Declared inside that specific program unit; visible only within that unit.

Nonlocal Variables

Visible within a program unit, but not declared inside that unit.

Global Variables

A special category of nonlocal variables declared outside function definitions.

1
Static Scoping (Introduced in Algol 60): Binds names to variables at compile time based on spatial/textual layout. Searches declarations locally first, then outward through enclosing static scopes.
2
Static Ancestors & Static Parent: Enclosing static scopes are called static ancestors; the nearest enclosing static ancestor is the static parent.
3
Languages with Nested Static Scopes: Ada, JavaScript, Common LISP, Scheme, Fortran 2003+, F#, and Python.
4
Global Scoping (C, C++, PHP, Python): Program consists of a sequence of function definitions in a file with variables declared outside functions.
C/C++
Declaration vs. Definition in C and C++:
• Declaration: Specifies only attributes (a declaration outside a function specifies that the variable is defined in another file).
• Definition: Specifies both attributes and storage allocation.

Lesson 3 • Step 5 of 6 • Temporal vs. Spatial

Dynamic Scoping Evaluation & Scope vs. Lifetime

Dynamic Scoping (Temporal / Call-Chain)

Rule
Based on the runtime calling sequence of program units (searches backward through the chain of active subprogram calls).
Pro
Advantage: Convenience (no need to pass every shared variable as an explicit parameter).

3 Disadvantages of Dynamic Scoping

1
No Local Variable Protection: While a subprogram executes, its local variables are visible to all subprograms it calls.
2
Impossible to Statically Type Check: Compiler cannot verify variable types before execution.
3
Poor Readability: Impossible to statically determine the type or declaration of a variable from source text.
Scope vs. Lifetime (Classic C/C++ Exam Case): Scope (where a name is visible) and Lifetime (how long memory exists) are different! A static variable declared inside a C/C++ function has local scope (visible only inside that function) but static lifetime (bound to memory for the entire program execution).

Lesson 3 • Step 6 of 6 • Visibility & Constants

Referencing Environments & Named Constants (const vs. readonly)

Ref
Referencing Environment: The collection of all names that are visible in a statement.
1
In a Static-Scoped Language: Local variables + all visible variables in all enclosing static scopes.
2
In a Dynamic-Scoped Language: Local variables + all visible variables in all currently active subprograms (a subprogram is active if its execution has begun but has not yet terminated).

Named Constants Overview

Def
A variable bound to a value only when it is bound to storage.
Pro
Improves readability and modifiability; used to parameterize programs.
Bind
Can be bound statically (called manifest constants) or dynamically (supported in Ada, C++, and Java using expressions of any kind).

C# Named Constants: const vs. readonly

1
const in C#: Values are bound statically at compile time (manifest constants).
2
readonly in C#: Values are dynamically bound at runtime (can be assigned when the object is constructed).

Lesson 4 • Step 1 of 7 • Primitive Types

Elementary Data Types: Integers & Arithmetic/Relational Operations

Elementary (Primitive) Data Types: Atomic data types directly supported by hardware or language specifications—primarily Numeric (Integer & Real), Boolean, and Character.
Int
Integer Data Type: Whole numbers with or without sign; forms an ordered subset within finite hardware bounds. Usually has no attributes besides its type. Supports Arithmetic, Relational, Assignment, and Bit operations.
1
Unary Arithmetic Operation (integer → integer): Operates on 1 operand, such as negation (-), identity (+), or prefix increment (++I in C).
2
Binary Arithmetic Operation (integer × integer → integer): Operates on 2 operands: addition (+), subtraction (-), multiplication (*), division (/), integer quotient (DIV), and remainder (MOD).
Examples: x := x + 1 (Pascal) • c = c * 1 (C).
3
Ternary Operation (Pr1 ? opr2 : opr3): Conditional shorthand for if...else (in C/Java)—returns opr2 if Pr1 is true, or opr3 if Pr1 is false.
Rel
Relational Operations (integer × integer → Boolean): Compares two data values (=, <, >, !=, <=, >=) and returns a Boolean (True or False) result.

Lesson 4 • Step 2 of 7 • Numeric Representations

Real Numbers, Complex Numbers & Rational Numbers

1
Real Numbers (Floating-Point): Numbers with a decimal point, with or without sign (1.25, +1.25, -1.25).
• Called real in Fortran and Pascal.
• Called float in C and C++.
• Supports arithmetic, relational, and assignment operations (with restrictions in Boolean operations).
2
Complex Numbers (Rosenberg): Ordered pair of real numbers expressible as a + bi (where a and b are real numbers and i² = -1). Represented in memory as a block of two storage locations (real part + imaginary part).
3
Rational Numbers: The quotient of two integers (a / b). Primary advantage is to avoid round-off and truncation problems encountered in floating-point and fixed-point representations of real numbers.

Booleans (5 Logical Operations) & Character Data Types

// 5 Boolean Operations Expressed as Conditional (if-then-else) Equivalents: 1. Conjunction (and): r and j = if r then j else false 2. Inclusive Disjunction (or): j or r = if j then true else r 3. Negation Complement (not): not k = if k then false else true 4. Implication (imp): x imp y = if x then y else true 5. Equivalence (equiv): r equiv j = if r then j else not j
ALG
ALGOL 60 Booleans: Uses literals true and false; strictly forbids mixing them with numeric values.
PAS
Pascal & Ada Booleans: Viewed as a predefined ordered enumerated type (FALSE < TRUE); can be redefined by the programmer since they are not literals.
PL/I
PL/I Booleans: False is any string containing all zeros or the empty string, while True must contain at least one non-zero.
Chr
Character Data Type ('B', 'K', 'g'): Single character value mapped to hardware/OS sets like ASCII. Operations include relational comparisons, assignment, and testing character class (letter, digit, special character).

Pointers: 3 Classic Problems, 3 Operations & Notation Table

Def
Why Use Pointers (Pascal, C, Ada): Identifier whose value is a reference to some object. Solves the problem of producing an undetermined number of items linked dynamically without explicitly naming every object.
1
Pointer Problem 1 (Aliasing): Several pointer variables pointing to the same object simultaneously.
2
Pointer Problem 2 (Unreferenced Objects / Garbage): Objects are no longer pointed at by any pointer variable.
3
Pointer Problem 3 (Location vs. Value): Ambiguity when a variable denotes either a memory location (l-value) or a value (r-value).
Ops
3 Operations on Pointers:
1. Assignment (setting pointer address)
2. Equality (comparing two pointer addresses)
3. Dereferencing (accessing the referenced target value/field)
