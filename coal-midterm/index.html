System Architecture, Hardware Organization & Evolution

A computer system is an interconnected electronic machine that accepts raw input data, processes it according to stored instructions, retains information in memory, and delivers meaningful output. Understanding how computers work requires examining both their logical programmer interface and their physical circuit implementation.

Part 3 • Stored-Program Architecture

The Von Neumann Model & Instruction Cycle

John von Neumann's Stored-Program Principle

Both program instructions and data being processed are stored together inside the same main memory.

Unified Memory

Prior to Von Neumann:

Early machines had to be manually rewired or physically reconfigured to switch tasks.

With Von Neumann:

Computers load different instruction sets into memory and switch programs without physical hardware changes.

Three Pillars of the Von Neumann Model

1. CPU

Executes instructions via Control Unit (CU) and ALU.

2. Main Memory

Holds both instructions and data.

3. I/O System

Links the computer system with external devices.

Performance Limitation — The Von Neumann Bottleneck: Because instructions and data share a single bus pathway between the CPU and main memory, transfer speed along that single channel limits overall processor throughput.

Part 4 • Hardware Anatomy

Core Subsystems: Processing, Control, Storage, Buses & I/O

Every computer system integrates functional units for Input, Output, Storage, Communication, Control, and Processing.

Central Processing Unit (CPU): Control & Computation

CU + ALU + Registers

The CPU executes instructions, processes data, and controls system operations using three internal subdivisions:

Control Unit (CU) — The System Coordinator

Directs and coordinates computer operations: fetches instructions from memory, decodes instructions, controls execution, and sends control signals to other components.

Arithmetic Logic Unit (ALU) — The Computation Engine

Performs Arithmetic operations (Addition, Subtraction, Multiplication, Division) and Logical operations (AND, OR, Comparison operations).

Registers — High-Speed CPU Storage

Small, immediate storage locations directly inside the CPU that hold temporary data, instructions, and addresses during active processing.

System Bus Architecture (Communication Pathways)

Transfers data, memory addresses, and control signals across components via three dedicated buses:

Data Bus

Transfers actual data between CPU, memory, and devices.

Address Bus

Carries memory addresses where data is stored or retrieved.

Control Bus

Transfers control signals that coordinate operations.

Input / Output (I/O) Subsystem

Input (User → Computer)

Provides data & instructions.
Examples: Keyboard, Mouse, Scanner, Microphone.

Output (Computer → User)

Presents processed results.
Examples: Monitor, Printer, Speakers.

Data Units, Numeric Formats, Radix Math & Binary Codes

Inside a digital computer, every piece of information—numbers, text characters, images, audio, and processor instructions—is encoded using binary values because electronic circuits reliably operate using two stable voltage states: $0$ (Low electrical state) and $1$ (High electrical state).

Part 1 • Digital Building Blocks

Hierarchy of Digital Data Units & Information Taxonomy

Fundamental Units of Computer Data

1. Bit (Binary Digit) 0 or 1

Smallest unit of information in a computer. Can only hold $0$ (Low state) or $1$ (High state).

Example: $1010_2$ contains $4\text{ bits}$.

2. Nibble 4 Bits

A group of four bits, equal to half of a byte.

$1\text{ Nibble} = 4\text{ Bits}$ (Ex: $1010_2 = 1\text{ nibble}$)

3. Byte 8 Bits = 2 Nibbles

A group of eight bits commonly used to represent a single character and measure memory size.

Ex: Character 'A' = $01000001_2$

4. Word 16, 32, or 64 bits

A group of bits processed by the CPU as one unit. Its bit width is called the word length.

Larger word length = more data handled at once.

Part 3 • Radix & Positional Notation

Number Systems (Base 10, Base 2, Base 8, Base 16)

Every number system is defined by its base (or radix), which specifies the number of available digit symbols and the powers used for positional place values. In positional notation, a digit's value depends on both the digit itself and its position:

$$\text{Positional Value} = \text{digit} \times \text{base}^{\text{position}}$$
System Base (Radix) Digits / Symbols Binary Grouping
Decimal Base 10 0–9 (10 digits) Human counting standard
Binary Base 2 0, 1 $1\text{ bit}$ per digit
Octal Base 8 0–7 (8 digits) $1\text{ Octal digit} = 3\text{ bits}$
Hexadecimal Base 16 0–9, A–F (16 symbols) $1\text{ Hex digit} = 4\text{ bits}$

Expanded Positional Notation Examples

Base 10 (Decimal) Expansion — $472_{10}$:

$$\begin{aligned} 472_{10} &= (4 \times 10^2) + (7 \times 10^1) + (2 \times 10^0) \\ &= 400 + 70 + 2 = \mathbf{472_{10}} \end{aligned}$$

Base 2 (Binary) Expansion — $1011_2$:

$$\begin{aligned} 1011_2 &= (1 \times 2^3) + (0 \times 2^2) + (1 \times 2^1) + (1 \times 2^0) \\ &= 8 + 0 + 2 + 1 = \mathbf{11_{10}} \end{aligned}$$

Octal & Hexadecimal Bit Shorthand:

Hexadecimal and Octal provide compact, human-readable shorthand for long binary strings.

$101_2 = 5_8$
Part 4 • Base Conversion Algorithms

Step-by-Step Number System Conversions (LaTeX Walkthroughs)

1. Decimal Integer $\rightarrow$ Binary

Division-Remainder Method

Repeatedly divide the decimal integer by $2$ and record each remainder until the quotient reaches $0$. Read the remainders upward from bottom to top.

Walkthrough: Convert $45_{10}$ to Binary

$$\begin{array}{r|r|c} \textbf{Division by 2} & \textbf{Quotient} & \textbf{Remainder} \\ \hline 45 \div 2 & 22 & 1 \;\; \text{(LSB)} \\ 22 \div 2 & 11 & 0 \\ 11 \div 2 & 5 & 1 \\ 5 \div 2 & 2 & 1 \\ 2 \div 2 & 1 & 0 \\ 1 \div 2 & 0 & 1 \;\; \text{(MSB)} \uparrow \end{array}$$

Reading remainders bottom-to-top $\uparrow$: $\quad 45_{10} = \mathbf{101101_2}$

2. Decimal Fraction $\rightarrow$ Binary

Repeated Multiplication

Repeatedly multiply the fractional part by $2$, record the resulting whole-number integer part ($0$ or $1$) at each step, and continue with the remaining fraction. Read integer parts from top to bottom.

Walkthrough: Convert $0.625_{10}$ to Binary

$$\begin{array}{l|c} \textbf{Multiplication Step} & \textbf{Integer Part} \\ \hline 0.625 \times 2 = 1.25 & \mathbf{1} \downarrow \\ 0.25 \times 2 = 0.50 & \mathbf{0} \downarrow \\ 0.50 \times 2 = 1.00 & \mathbf{1} \downarrow \end{array}$$

Reading integer parts top-to-bottom $\downarrow$: $\quad 0.625_{10} = \mathbf{0.101_2}$

3. Binary $\rightarrow$ Decimal

Weight Summation Method

Assign powers of $2$ ($2^0, 2^1, 2^2, 2^3, \dots$) from right to left, multiply each bit by its positional weight, and sum the products:

$$\begin{aligned} 1011_2 &= (1 \times 2^3) + (0 \times 2^2) + (1 \times 2^1) + (1 \times 2^0) \\ &= 8 + 0 + 2 + 1 = \mathbf{11_{10}} \end{aligned}$$

4. Binary $\rightarrow$ Octal & Hexadecimal

3-Bit & 4-Bit Grouping

Binary $\rightarrow$ Octal (3-bit groups)

Partition bits into sets of $3$ from right to left:

$$\underbrace{101}_{5_8}\;\underbrace{101}_{5_8} \implies 101101_2 = \mathbf{55_8}$$

Binary $\rightarrow$ Hex (4-bit groups)

Partition bits into sets of $4$ from right to left (pad leading $0$s):

$$\underbrace{0010}_{2_{16}}\;\underbrace{1101}_{\text{D}_{16}} \implies 101101_2 = \mathbf{2\text{D}_{16}}$$

Part 5 • Specialized Binary & Character Coding

Weighted Codes, Non-Weighted Codes & Character Encoding Standards

Weighted Binary Codes

Fixed Positional Weights

Assigns a fixed numerical weight to each bit position so the value of each bit depends on its place:

8421 Code (BCD)

Weights: 8, 4, 2, 1

Also called Binary Coded Decimal; encodes each decimal digit separately using 4 bits.

2421 Code

Weights: 2, 4, 2, 1

Represents decimal digits and features self-complementing properties.

5211 Code

Weights: 5, 2, 1, 1

Weighted 4-bit code used for decimal digit representation.

BCD Conversion Walkthrough — Convert $59_{10}$ to BCD:

$$\text{Split digits: } 5 \rightarrow 0101_2, \quad 9 \rightarrow 1001_2 \implies 59_{10} = \mathbf{0101\;1001_{\text{BCD}}}$$

Non-Weighted Binary Codes

Rule-Defined Values

Does not assign fixed positional weights to bit positions; values follow specific encoding rules:

Excess-3 Code (Self-Complementary BCD Code)

Created by adding $3$ ($0011_2$) to the 8421 BCD value of each decimal digit (used for binary arithmetic correction).

$$\text{Convert } 5_{10}: \quad 5_{\text{BCD}} = 0101_2 \;\xrightarrow{+\,0011_2}\; 0101_2 + 0011_2 = \mathbf{1000_{\text{Excess-3}}}$$

Gray Code (Reflected Binary Code / Unit Distance Code)

Consecutive values differ by only one bit, minimizing transition errors in digital hardware where sudden multi-bit changes could cause false readings.

Module 04 • Processor Instruction Architecture

Instruction Set Architecture (ISA), Formats & Categories

The Instruction Set Architecture (ISA) acts as the contract between software and hardware—specifying the machine instructions a processor understands, how binary instructions are structured, where operands reside, and how the CPU executes programs step by step.

Part 1 • The Software–Hardware Contract

What the ISA Defines & How Abstraction Works

Five Core Specifications of an ISA

1. Instruction Set

The complete set of operations that the processor can perform.

2. Registers

Small, fast storage locations directly inside the CPU.

3. Data Types

Types of data values supported and processed by instructions.

4. Instruction Formats

Binary layout and structural arrangement of machine instructions.

5. Addressing Methods

Mechanisms used by instructions to locate operands in registers, memory, or constants.

ISA Abstraction in Action

Because the ISA shields programmers from physical circuit details, a developer can issue a single symbolic instruction while the processor orchestrates the underlying electronics:

Software Command: ADD R1, R2

Hidden hardware tasks handled automatically by the processor:

Control signals Data movement ALU hardware ops
Four-Step Execution Cycle: Fetch ➔ Decode ➔ Execute ➔ Store
Part 2 • Instruction Layout & Address Count

Machine Instruction Anatomy & Address Format Classification

Field 1 • Operation Code

Opcode

Specifies the operation to be performed by the processor (e.g., ADD, SUB, LOAD, STORE).

Field 2 • Data / Location Reference

Operand Field

Specifies the data or location used by the instruction (may contain register numbers, memory addresses, or immediate values).

Instruction Format Operand Structure Assembly Example Mathematical Effect Trade-offs & Notes
Three-Address One destination operand + two source operands (Opcode Dest, Src1, Src2) ADD R1, R2, R3 $\text{R1} = \text{R2} + \text{R3}$ + Fewer instructions needed
− Larger binary instruction size
Two-Address One destination operand + one source operand (Opcode Dest, Src) ADD R1, R2 $\text{R1} = \text{R1} + \text{R2}$ + Smaller instruction size
− May require more instructions

Zero-Address Contains no explicit operand field; uses implicit stack-based operations ADD $\text{Stack Top} \leftarrow \text{Pop} + \text{Pop}$ Processor pops operands from and pushes results onto the stack.
Part 3 • Operands & Data Representation

Supported Processor Data Types & Operand Modes

Four Processor Data Types

Integer

Whole numbers without decimals ($10, -5, 25, 100, -10$). Used for counting, arithmetic operations, and index values.

Floating-Point

Numbers containing fractional decimal values ($3.14, 25.5$). Used for scientific calculations, engineering, and graphics.

Character

Single letters, digits, or symbols (A, B, %, 5) stored via ASCII or Unicode.

Boolean

Logical truth values ($\text{True} = 1$, $\text{False} = 0$) used in logical operations and decision-making.

Operand Categories (Where Data Comes From)

An operand is the data value or location operated on by an instruction (e.g., R1 and R2 in ADD R1, R2):

1. Immediate Operand ADD R1, 5

Constant value ($5$) is embedded directly inside the instruction itself.

2. Register Operand ADD R1, R2

Data is held inside a high-speed internal CPU register.

3. Memory & I/O Operands LOAD R1, Address

Memory Operand: Data resides in main memory and is accessed by memory address. I/O Operand: Retrieves or sends data to external peripherals (such as keyboards or printers).
