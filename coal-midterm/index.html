Computer Architecture vs. Computer Organization

What the computer does Programmer-Visible

Computer Architecture

Refers to the attributes of a computer system that are visible to the programmer and affect how programs operate.

Includes:

  • Instruction set design
  • Data representation
  • Memory addressing methods
  • Input/Output mechanisms
  • Timing and control mechanisms
Example: The instructions available to a processor and how programmers interact with the hardware.
How the computer does it Physical Implementation

Computer Organization

Refers to the physical implementation and arrangement of hardware components that realize the computer architecture.

Includes:

  • Hardware components
  • Data paths
  • Control signals
  • Memory technology
  • Interconnection between components
Core Relationship: Computer Architecture = What the computer does • Computer Organization = How the computer does it.

The Von Neumann Model & Fetch–Decode–Execute Cycle

John von Neumann

Stored Program Concept

→ Data and instructions are stored together in the same memory.

Before this model:

Programs were manually configured for different tasks.

With the Von Neumann Model:

Computers can store instructions and execute different programs without physical changes.

Three Main Components of Von Neumann Model

1. CPU

Executes instructions. Contains:

• Control Unit (CU)
• ALU

2. Main Memory

Stores together:

• Program instructions
• Data being processed

3. I/O System

Communicates between:

• Computer system
• External devices

⚠️
Von Neumann Bottleneck: A single pathway limits communication speed between the CPU and memory because data and instructions share the same bus.

Fetch–Decode–Execute Cycle

Process flow: Instruction in Memory → Fetch → Decode → Execute → Store Result

STEP 1 Active
1. Fetch

The CPU retrieves an instruction from memory.

STEP 2 Next
2. Decode

The Control Unit (CU) interprets the instruction.

STEP 3 Wait
3. Execute

The CPU (ALU) performs the required operation.

STEP 4 Complete
4. Store Result

Saves the processed result back to register or memory.

2-3 & 2-4

Weighted & Non-Weighted Binary Codes

2-3 Weighted Binary Codes

8421 • 2421 • 5211

A weighted binary code assigns a fixed value (weight) to each bit position. The value of each bit depends on its position, and binary place values are based on powers of $2$.

Binary Value Computation Example: Convert $1011_2 \rightarrow \text{Decimal}$

$$\begin{aligned} 1011_2 &= (1 \times 2^3) + (0 \times 2^2) + (1 \times 2^1) + (1 \times 2^0) \\ &= 8 + 0 + 2 + 1 \\ &= \mathbf{11_{10}} \end{aligned}$$

8421 Code (BCD)

Weights: 8 4 2 1

Also called Binary Coded Decimal (BCD). Each decimal digit is represented separately using 4 bits.

2421 Code

Weights: 2 4 2 1

Used for decimal digit representation. Has self-complementing properties.

5211 Code

Weights: 5 2 1 1

A weighted binary code using $5\ 2\ 1\ 1$ weights for representing decimal digits.

2-4 Non-Weighted Binary Codes

Excess-3 • Gray Code

Non-weighted codes do not assign fixed positional weights to each binary digit. The value is determined by coding rules rather than bit position.

Excess-3 Code
BCD + 0011₂

A non-weighted and self-complementary BCD code created by adding $3$ ($0011_2$) to each decimal digit's BCD representation.

Example: Convert $5_{10}$ to Excess-3

1. Convert $5$ into BCD: $5_{10} = 0101_2$  |  2. Add $3$ ($0011_2$):

$$\begin{array}{r} 0101_2 \\ + \; 0011_2 \\ \hline \mathbf{1000_{\text{Excess-3}}} \end{array} \implies 5_{10} = \mathbf{1000}\text{ (Excess-3)}$$
Gray Code
1-Bit Change

A non-weighted binary code where each consecutive value changes by only one bit.

  • • Also known as: Reflected Binary Code (RBC) • Unit Distance Code
  • • Purpose: Reduces errors during transitions; commonly used in digital systems where sudden changes may cause errors.

Number Systems & Positional Notation

A number system is a method of representing numbers using symbols and digits. Each number system has a base or radix, which determines the number of available digits and the place values used.

Number System Base (Radix) Digits Used Bit Relationship
Decimal Base 10 0–9 Human standard ($10$ digits)
Binary Base 2 0 and 1 2 stable circuit states
Octal Base 8 0–7 $1\text{ Octal digit} = 3\text{ bits}$
Hexadecimal Base 16 0–9, A–F $1\text{ Hex digit} = 4\text{ bits}$
Positional Notation Concept

In positional notation, the value of a digit depends on (1) the digit itself and (2) its position in the number:

$$\text{Value} = \text{digit} \times \text{base}^{\text{position}}$$

Expanded Form Examples (LaTeX Computations)

1. Decimal System (Base 10) — Example: $472_{10}$

$$\begin{aligned} 472_{10} &= (4 \times 10^2) + (7 \times 10^1) + (2 \times 10^0) \\ &= 400 + 70 + 2 = \mathbf{472} \end{aligned}$$

2. Binary System (Base 2) — Example: $1011_2$

$$\begin{aligned} 1011_2 &= (1 \times 2^3) + (0 \times 2^2) + (1 \times 2^1) + (1 \times 2^0) \\ &= 8 + 0 + 2 + 1 = \mathbf{11_{10}} \end{aligned}$$

3. Octal System (Base 8)

Uses eight digits: $0\text{–}7$.

$$1\text{ Octal digit} = 3\text{ Binary bits}$$

Example: $101_2 = 5_8$

4. Hexadecimal (Base 16)

Uses sixteen symbols: $0\text{–}9, \text{A–F}$.

$$1\text{ Hex digit} = 4\text{ Binary bits}$$

$\text{A}=10, \text{B}=11 \dots \text{F}=15$

Number System Conversions (Step-by-Step LaTeX Computations)

Method 1 Division-Remainder Method

Decimal $\rightarrow$ Binary Conversion

  1. Divide the decimal number by $2$.
  2. Record the remainder ($0$ or $1$).
  3. Continue dividing until the quotient becomes $0$.
  4. Read the remainders from bottom to top (upward).

Example: Convert $45_{10}$ to binary

$$\begin{array}{c|c|c} \textbf{Division} & \textbf{Quotient} & \textbf{Remainder} \\ \hline 45 \div 2 & 22 & 1 \;\; \text{(LSB)} \\ 22 \div 2 & 11 & 0 \\ 11 \div 2 & 5 & 1 \\ 5 \div 2 & 2 & 1 \\ 2 \div 2 & 1 & 0 \\ 1 \div 2 & 0 & 1 \;\; \text{(MSB)} \uparrow \end{array}$$

Read remainders upward $\uparrow$: $\quad 45_{10} = \mathbf{101101_2}$

Method 2 Repeated Multiplication Method

Decimal Fraction $\rightarrow$ Binary Conversion

  1. Multiply the fractional part by $2$.
  2. Record the integer part ($0$ or $1$).
  3. Continue using the new fractional value until fraction becomes $.0$ (read top to bottom).

Example: Convert $0.625_{10}$ to binary

$$\begin{array}{l|c} \textbf{Operation} & \textbf{Integer Part} \\ \hline 0.625 \times 2 = 1.25 & \mathbf{1} \downarrow \\ 0.25 \times 2 = 0.5 & \mathbf{0} \downarrow \\ 0.5 \times 2 = 1.0 & \mathbf{1} \downarrow \end{array}$$

Answer: $\quad 0.625_{10} = \mathbf{0.101_2}$

Method 3 Weight Summation Method

Binary $\rightarrow$ Decimal Conversion

  1. Assign powers of $2$ ($2^0, 2^1, 2^2, \dots$) to each bit from right to left.
  2. Multiply each bit by its positional weight.
  3. Add all values together.

Example: Convert $1011_2$ to Decimal

$$\begin{aligned} 1011_2 &= (1 \times 2^3) + (0 \times 2^2) + (1 \times 2^1) + (1 \times 2^0) \\ &= 8 + 0 + 2 + 1 = \mathbf{11_{10}} \end{aligned}$$
Methods 4 & 5 Bit-Grouping Methods

Binary $\rightarrow$ Octal (3 bits) & Binary $\rightarrow$ Hexadecimal (4 bits)

Binary $\rightarrow$ Octal

Group binary digits into groups of 3 from the right.

Example: Convert $101101_2$

$$\underbrace{101}_{5_8} \; \underbrace{101}_{5_8} \implies \mathbf{55_8}$$

Binary $\rightarrow$ Hexadecimal

Group binary digits into groups of 4 from the right (pad leading zeros).

Example: Convert $101101_2$

$$\underbrace{0010}_{2_{16}} \; \underbrace{1101}_{\text{D}_{16}} \implies \mathbf{2\text{D}_{16}}$$

Logical Operators & Digital Logic Gates

Logical operators are operations used to compare and manipulate binary values ($0 = \text{False / OFF}$, $1 = \text{True / ON}$). They are the foundation of digital circuits and computer decision-making processes, implemented in hardware using logic gates.

AND → "All must be 1" OR → "One is enough" NOT → "Opposite value" XOR → "Different = 1"

Basic Logic Operators & Summary

AND Operator

Symbol: $\land$

Produces an output of $1$ only when all inputs are $1$. If any input is $0$, the output becomes $0$.

Expression: $A \land B$  or  $Y = A \cdot B$

OR Operator

Symbol: $\lor$

Produces an output of $1$ when at least one input is $1$. Output is $0$ only when all inputs are $0$.

Expression: $A \lor B$  or  $Y = A + B$

NOT Operator (Inverter)

Symbol: $\neg$

Reverses the input value ($1$ becomes $0$ and $0$ becomes $1$). Also called an inverter.

Expression: $\neg A$  or  $Y = \overline{A}$

XOR (Exclusive OR)

Symbol: $\oplus$

Produces an output of $1$ when the inputs are different. Produces $0$ when inputs are the same.

Expression: $A \oplus B$

Operands & Types of Operands

An operand is the data or value used by an instruction. For example, in ADD R1, R2, the operands are R1 and R2.

1. Immediate Operand

Value is included directly in the instruction.

ADD R1, 5

2. Register Operand

Data is stored inside a CPU register.

ADD R1, R2

3. Memory Operand

Data is stored in memory (accessed by address).

LOAD R1, Address
4-3

Instruction Format (Opcode, Operand Field & Address Formats)

Instruction format defines how an instruction is arranged in binary form. An instruction contains two core parts:

Part 1 • Operation Code ADD, SUB, LOAD, STORE

Opcode

Specifies the operation performed by the processor.

Part 2 • Data / Location Registers • Memory Addresses • Immediate Values

Operand Field

Specifies the data or location used by the instruction.

Three-Address Instruction

Uses two source operands and one destination.

Format: Opcode Dest, Src1, Src2

ADD R1, R2, R3

$\text{R1} = \text{R2} + \text{R3}$

+ Advantage: Requires fewer instructions

− Disadvantage: Larger instruction size

Two-Address Instruction

Uses one destination and one source operand.

Format: Opcode Dest, Src

ADD R1, R2

$\text{R1} = \text{R1} + \text{R2}$

+ Advantage: Smaller instruction size

− Disadvantage: May require more instructions

One-Address Instruction

Uses one explicit operand, commonly with an accumulator (ACC) register.

Format: Opcode Operand

ADD X

$\text{ACC} = \text{ACC} + \text{X}$

Uses an accumulator to store intermediate results.

Zero-Address Instruction

Contains no explicit operand field; uses stack-based operations.

Format: Opcode only

ADD

$\text{TOS} \leftarrow \text{Pop} + \text{Pop}$

The processor gets operands from and pushes results to the stack.

Instruction Types (Grouped by Purpose)

1. Data Transfer

Moves data between locations (registers and memory).

LOAD STORE MOVE
Ex: LOAD R1, Address
Meaning: Memory data → Register

2. Arithmetic

Performs mathematical calculations.

ADD SUB MUL DIV

Operations: Addition, Subtraction, Multiplication, Division.

3. Logical

Performs logical and bit-level operations.

AND OR NOT XOR

Used for: Bit manipulation • Comparisons • Decision operations.

4. Control Flow

Changes the normal sequence of instruction execution.

Jump Branch Call Return

Used for: Loops • Conditions • Functions.

5. Input/Output (I/O)

Handles communication between the processor and external devices.

Examples: Reading input • Sending output

Devices: Keyboard • Monitor • External hardware

Chapter 01: Computer Systems Key Points

Page 8
  • • Set: A collection of unordered, distinct, and well-defined objects. Cardinality ($|S|$) = number of elements. Membership ($x \in S$) means "$x$ is in $S$."
  • • Computer Architecture → programmer-visible design of a computer system (What the computer does).
  • • Computer Organization → hardware implementation of the architecture (How the computer does it).
  • • CPU consists of: Control Unit (CU), Arithmetic Logic Unit (ALU), and Registers.
  • • Von Neumann Model: Uses stored-program concept; data and instructions share the same memory.
  • • Fetch–Decode–Execute cycle: Fetch (Get instruction) → Decode (Interpret instruction) → Execute (Perform operation).
  • • Von Neumann Bottleneck: Single pathway limits communication speed between CPU and memory.
  • • Levels of Abstraction: Level 0 (Digital Logic) → Level 1 (Microarchitecture) → Level 2 (ISA) → Level 3 (Operating System Machine Level) → Level 4 (Assembly Language) → Level 5 (High-Level Language).
  • • Computer Generations: 1st (Vacuum Tubes) → 2nd (Transistors) → 3rd (Integrated Circuits) → 4th (Microprocessors) → 5th (AI and Parallel Processing).
  • • Integration Scale: SSI (Smallest: 10–100) → MSI → LSI → VLSI (up to 1M) → ULSI (millions to billions) → GSI (Largest: $>1\text{B}$ transistors).

Chapter 02: Numbers & Characters Key Points

Pages 18–19
  • • Digital Representation: Stores information using binary values ($0$ and $1$).
  • • Data Units: Bit = smallest unit ($0$ or $1$) • Nibble = $4\text{ bits}$ • Byte = $8\text{ bits}$ ($2\text{ nibbles}$) • Word = unit of data CPU processes at a time ($16, 32, 64\text{-bit}$).
  • • Character Codes: ASCII ($7\text{-bit}$, $128$ chars, $0\text{–}127$) • Extended ASCII ($8\text{-bit}$, $0\text{–}255$) • Unicode (global languages & symbols) • EBCDIC (IBM mainframes).
  • • Weighted Codes: Each bit position has an assigned weight (8421 BCD, 2421, 5211).
  • • Non-Weighted Codes: Excess-3 (self-complementary, $\text{BCD} + 3 / 0011_2$) • Gray Code (consecutive values differ by only $1\text{ bit}$, reduces transition errors).
  • • Number Systems: Decimal (Base 10, $0\text{–}9$) • Binary (Base 2, $0\text{–}1$) • Octal (Base 8, $0\text{–}7$) • Hexadecimal (Base 16, $0\text{–}9, \text{A–F}$).
  • • Conversions: Decimal $\to$ Binary (Division-Remainder) • Fraction $\to$ Binary (Repeated Multiplication) • Binary $\to$ Decimal (Weight Summation) • Binary $\to$ Octal (Group $3\text{ bits}$) • Binary $\to$ Hex (Group $4\text{ bits}$).
  • • Numeric Representations: Fixed-Point (fixed decimal position, faster, simple hardware, limited range) vs. Floating-Point (variable decimal point, scientific/engineering, larger range) vs. BCD ($4\text{ bits}$ per decimal digit).

Chapter 03: Logical Operators Key Points

Page 21
  • • Quick Rules: AND ($\land$) → "All must be 1" • OR ($\lor$) → "One is enough" • NOT ($\neg$) → "Opposite value" • XOR ($\oplus$) → "Different = 1".
  • • Logical Operator: Used to process and manipulate binary values ($0 = \text{False}$, $1 = \text{True}$); forms the basis of digital decision-making in computer systems.
  • • AND Operation: Output is $1$ only when all inputs are $1$; if any input is $0$, output is $0$.
  • • OR Operation: Output is $1$ when at least one input is $1$; output is $0$ only when all inputs are $0$.
  • • NOT Operation (Inverter): Reverses the input value ($1 \to 0$ and $0 \to 1$).
  • • XOR (Exclusive OR): Output is $1$ when inputs are different; output is $0$ when inputs are the same.
  • • Logic Gates & ALU: Logic gates are hardware components that implement logical operations in digital circuits; the ALU uses them for calculations and decision-making inside the CPU.

Chapter 04: Instruction Set Architecture (ISA) Key Points

Pages 26–27
  • • ISA (Instruction Set Architecture): Acts as the interface between software and hardware; defines how programs communicate with the processor.
  • • ISA Abstraction: Hides the complexity of hardware details from programmers so software developers work with simpler instructions.
  • • Instruction Cycle: Fetch (Retrieves instruction from memory) → Decode (Interprets what instruction means) → Execute (Performs required operation) → Store (Saves the result).
  • • Data Types: Integer (whole numbers), Floating-Point (decimals), Character (ASCII/Unicode symbols), Boolean (True/False).
  • • Opcode vs. Operand: Opcode specifies the operation performed; Operand is the data or value used (Immediate, Register, or Memory operand).
  • • Address Formats: Three-Address (Dest + 2 Sources) • Two-Address (Dest + 1 Source) • One-Address (uses Accumulator `ACC`) • Zero-Address (uses Stack).
  • • Instruction Types: Data Transfer (`LOAD`, `STORE`, `MOVE`) • Arithmetic (`ADD`, `SUB`, `MUL`, `DIV`) • Logical (`AND`, `OR`, `NOT`, `XOR`) • Control Flow (`Jump`, `Branch`, `Call`, `Return`) • Input/Output (I/O).
