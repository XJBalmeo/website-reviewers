Module 01 • Foundations of Computing Machinery

System Architecture, Hardware Organization & Evolution

A computer system is an interconnected electronic machine that accepts raw input data, processes it according to stored instructions, retains information in memory, and delivers meaningful output. Understanding how computers work requires examining both their logical programmer interface and their physical circuit implementation.

Part 3 • Stored-Program Architecture

The Von Neumann Model & Instruction Cycle

John von Neumann's Stored-Program Principle

Both program instructions and data being processed are stored together inside the same main memory.

Unified Memory

Prior to Von Neumann:

Early machines had to be manually rewired or physically reconfigured to switch tasks.

With Von Neumann:

Computers load different instruction sets into memory and switch programs without physical hardware changes.

Three Pillars of the Von Neumann Model

1. CPU

Executes instructions via Control Unit (CU) and ALU.

2. Main Memory

Holds both instructions and data.

3. I/O System

Links the computer system with external devices.

Performance Limitation — The Von Neumann Bottleneck: Because instructions and data share a single bus pathway between the CPU and main memory, transfer speed along that single channel limits overall processor throughput.

Part 4 • Hardware Anatomy

Core Subsystems: Processing, Control, Storage, Buses & I/O

Every computer system integrates functional units for Input, Output, Storage, Communication, Control, and Processing.

Central Processing Unit (CPU): Control & Computation

CU + ALU + Registers

The CPU executes instructions, processes data, and controls system operations using three internal subdivisions:

Control Unit (CU) — The System Coordinator

Directs and coordinates computer operations: fetches instructions from memory, decodes instructions, controls execution, and sends control signals to other components.

Arithmetic Logic Unit (ALU) — The Computation Engine

Performs Arithmetic operations (Addition, Subtraction, Multiplication, Division) and Logical operations (AND, OR, Comparison operations).

Registers — High-Speed CPU Storage

Small, immediate storage locations directly inside the CPU that hold temporary data, instructions, and addresses during active processing.

System Bus Architecture (Communication Pathways)

Transfers data, memory addresses, and control signals across components via three dedicated buses:

Data Bus

Transfers actual data between CPU, memory, and devices.

Address Bus

Carries memory addresses where data is stored or retrieved.

Control Bus

Transfers control signals that coordinate operations.

Input / Output (I/O) Subsystem

Input (User → Computer)

Provides data & instructions.
Examples: Keyboard, Mouse, Scanner, Microphone.

Output (Computer → User)

Presents processed results.
Examples: Monitor, Printer, Speakers.

Von Neumann & Bus Details
Program Counter (PC) & Multipoint Buses
  • • Program Counter (PC): Special CPU register that holds the address of the next instruction to be executed and automatically increments on each fetch, saving instruction memory space.
  • • System Bus Model Refinement: Includes a Power Bus and optional separate I/O Bus. Because a multipoint bus is a shared resource, access is governed by hardware protocols.
  • • Alan Turing's Contribution: First to envisage and prove the possibility of universal machines capable of reading and executing programmed instructions for any conceivable task.
Abstraction Boundary
System vs. Applications Programmers
  • • Levels 1–3 (System Programmers): Numeric languages (long series of numbers). Levels 2 and 3 are always interpreted (by microprogram/hardwired control or OS). Built by system programmers who develop virtual machines and interpreters.
  • • Levels 4–5 (Applications Programmers): Contain human-meaningful words and abbreviations (e.g., C, Java, BASIC, LISP, Prolog) usually supported by translation (assembler/compiler).
  • • Below Level 0 (Device Level): Individual transistors and wires in the domain of electrical engineering; 1-bit transistor memories group into 16-, 32-, or 64-bit registers.

Part 6 • Quantitative Performance Evaluation

Measuring Performance: Execution Time, MIPS, CPI/IPC, Benchmarks, Speedup & Amdahl's Law

Execution time is the most direct indicator of how long a user waits for a program to complete—systems that execute programs in less time have higher performance. Alongside speed, ease of programming and binary compatibility across processor families also govern architectural choices.

Rate & Cycle Metrics MIPS • CPI • IPC

MIPS, CPI & IPC

• MIPS (Millions of Instructions Per Second): Execution rate calculated by dividing instruction count by execution time: $$\text{MIPS} = \frac{\text{Instructions Executed}}{\text{Execution Time} \times 10^6}$$ Limitation: MIPS does not account for the fact that different ISAs require different instruction counts to perform the same task—so a computer with a higher MIPS rating can still take longer to finish a program if it executes many more instructions.

• CPI (Cycles Per Instruction) & IPC (Instructions Per Cycle): Reciprocal metrics ($\text{IPC} = 1 / \text{CPI}$): $$\text{CPI} = \frac{\text{Total Clock Cycles}}{\text{Instructions Executed}}, \quad \text{IPC} = \frac{\text{Instructions Executed}}{\text{Total Clock Cycles}}$$ Low CPI (or High IPC) indicates better performance. Rearranging gives $\text{Instructions} = \frac{\text{Cycles}}{\text{CPI}}$ and $\text{Cycles} = \text{CPI} \times \text{Instructions}$.

LaTeX Walkthroughs Cycle Math

CPI & IPC Solved Computations

Example 1: Loop CPI & IPC

A $100$-instruction loop runs $42$ times taking $16{,}000$ cycles:

$$\begin{aligned} \text{Instructions} &= 100 \times 42 = 4{,}200 \\ \text{CPI} &= \frac{16{,}000}{4{,}200} = \mathbf{3.81}, \quad \text{IPC} = \frac{4{,}200}{16{,}000} = \mathbf{0.26} \end{aligned}$$

Example 2: Finding Instruction Count & IPC

• Given $1{,}000{,}000$ cycles and $\text{CPI} = 40$:

$$\text{Instructions} = \frac{1{,}000{,}000}{40} = \mathbf{25{,}000\text{ instructions}}$$

• Given $35{,}000$ instructions in $17{,}000$ cycles:

$$\text{IPC} = \frac{35{,}000}{17{,}000} \approx \mathbf{2.06}$$
Standardized Workloads Benchmarks & Means

Benchmark Suites & Averaging Means

• Benchmark Suites: Standardized collections of typical programs used to compare computer performance fairly. Architects use multiple benchmarks because different programs stress different aspects of a system, and scores are based on total execution time rather than instruction rate.

Geometric vs. Arithmetic Mean (Values: $4, 2, 4, 82$)

Benchmark suites prefer the geometric mean because a single extreme outlier skews the arithmetic mean heavily:

$$\text{Arithmetic Mean} = \frac{4 + 2 + 4 + 82}{4} = \mathbf{23}$$ $$\text{Geometric Mean} = \sqrt[4]{4 \times 2 \times 4 \times 82} = \mathbf{7.16}$$

Speedup & Amdahl's Law ("Make the Common Case Fast")

Speedup Ratio Formula

Ratio of execution time before (Old Time) to execution time after (New Time) an improvement:

$$\text{Speedup} = \frac{\text{Execution Time}_{\text{old}}}{\text{Execution Time}_{\text{new}}}$$ $$\text{New Time} = \frac{\text{Old Time}}{\text{Speedup}}$$
  • • $25\text{ s} \to 15\text{ s}: \; 25 / 15 = \mathbf{1.67\times}$
  • • $200\text{ s} \to 150\text{ s}: \; 200 / 150 = \mathbf{1.33\times}$
  • • $120\text{ s} \to 80\text{ s}: \; 120 / 80 = \mathbf{1.50\times}$
  • • $78\text{ s}$ with $3\times$ speedup: $78 / 3 = \mathbf{26\text{ s}}$

Amdahl's Law Equations

The performance gain from optimizing a single component is limited by the fraction of time ($\text{Frac}_{\text{used}}$) that component is actually used:

$$T_{\text{new}} = T_{\text{old}} \times \left( \text{Frac}_{\text{unused}} + \frac{\text{Frac}_{\text{used}}}{\text{Speedup}_{\text{used}}} \right)$$ $$\text{Speedup}_{\text{overall}} = \frac{1}{\text{Frac}_{\text{unused}} + \dfrac{\text{Frac}_{\text{used}}}{\text{Speedup}_{\text{used}}}}$$

As $\text{Speedup}_{\text{used}} \to \infty$, maximum possible speedup converges to $\dfrac{1}{\text{Frac}_{\text{unused}}}$.

Hardware Multiplier Walkthrough ($200\text{ cycles software} \to 4\text{ cycles hardware} \implies \text{Speedup}_{\text{used}} = 200/4 = 50$):

• If multiplication is used $10\%$ of time ($\text{Frac}_{\text{used}}=0.1, \text{Frac}_{\text{unused}}=0.9$): $\quad \text{Speedup} = \dfrac{1}{0.9 + 0.1/50} = \mathbf{1.11\times}$
• If multiplication is used $40\%$ of time ($\text{Frac}_{\text{used}}=0.4, \text{Frac}_{\text{unused}}=0.6$): $\quad \text{Speedup} = \dfrac{1}{0.6 + 0.4/50} = \mathbf{1.64\times}$

Data Units, Numeric Formats, Radix Math & Binary Codes

Inside a digital computer, every piece of information—numbers, text characters, images, audio, and processor instructions—is encoded using binary values because electronic circuits reliably operate using two stable voltage states: $0$ (Low electrical state) and $1$ (High electrical state).

Part 1 • Digital Building Blocks

Hierarchy of Digital Data Units & Information Taxonomy

Fundamental Units of Computer Data

1. Bit (Binary Digit) 0 or 1

Smallest unit of information in a computer. Can only hold $0$ (Low state) or $1$ (High state).

Example: $1010_2$ contains $4\text{ bits}$.

2. Nibble 4 Bits

A group of four bits, equal to half of a byte.

$1\text{ Nibble} = 4\text{ Bits}$ (Ex: $1010_2 = 1\text{ nibble}$)

3. Byte 8 Bits = 2 Nibbles

A group of eight bits commonly used to represent a single character and measure memory size.

Ex: Character 'A' = $01000001_2$

4. Word 16, 32, or 64 bits

A group of bits processed by the CPU as one unit. Its bit width is called the word length.

Larger word length = more data handled at once.

Every number system is defined by its base (or radix), which specifies the number of available digit symbols and the powers used for positional place values. In positional notation, a digit's value depends on both the digit itself and its position:

$$\text{Positional Value} = \text{digit} \times \text{base}^{\text{position}}$$

Part 4 • Base Conversion Algorithms

Step-by-Step Number System Conversions (LaTeX Walkthroughs)

1. Decimal Integer $\rightarrow$ Binary

Division-Remainder Method

Repeatedly divide the decimal integer by $2$ and record each remainder until the quotient reaches $0$. Read the remainders upward from bottom to top.

Walkthrough: Convert $45_{10}$ to Binary

$$\begin{array}{r|r|c} \textbf{Division by 2} & \textbf{Quotient} & \textbf{Remainder} \\ \hline 45 \div 2 & 22 & 1 \;\; \text{(LSB)} \\ 22 \div 2 & 11 & 0 \\ 11 \div 2 & 5 & 1 \\ 5 \div 2 & 2 & 1 \\ 2 \div 2 & 1 & 0 \\ 1 \div 2 & 0 & 1 \;\; \text{(MSB)} \uparrow \end{array}$$

Reading remainders bottom-to-top $\uparrow$: $\quad 45_{10} = \mathbf{101101_2}$

2. Decimal Fraction $\rightarrow$ Binary

Repeated Multiplication

Repeatedly multiply the fractional part by $2$, record the resulting whole-number integer part ($0$ or $1$) at each step, and continue with the remaining fraction. Read integer parts from top to bottom.

Walkthrough: Convert $0.625_{10}$ to Binary

$$\begin{array}{l|c} \textbf{Multiplication Step} & \textbf{Integer Part} \\ \hline 0.625 \times 2 = 1.25 & \mathbf{1} \downarrow \\ 0.25 \times 2 = 0.50 & \mathbf{0} \downarrow \\ 0.50 \times 2 = 1.00 & \mathbf{1} \downarrow \end{array}$$

Reading integer parts top-to-bottom $\downarrow$: $\quad 0.625_{10} = \mathbf{0.101_2}$

3. Binary $\rightarrow$ Decimal

Weight Summation Method

Assign powers of $2$ ($2^0, 2^1, 2^2, 2^3, \dots$) from right to left, multiply each bit by its positional weight, and sum the products:

$$\begin{aligned} 1011_2 &= (1 \times 2^3) + (0 \times 2^2) + (1 \times 2^1) + (1 \times 2^0) \\ &= 8 + 0 + 2 + 1 = \mathbf{11_{10}} \end{aligned}$$

4. Binary $\rightarrow$ Octal & Hexadecimal

3-Bit & 4-Bit Grouping

Binary $\rightarrow$ Octal (3-bit groups)

Partition bits into sets of $3$ from right to left:

$$\underbrace{101}_{5_8}\;\underbrace{101}_{5_8} \implies 101101_2 = \mathbf{55_8}$$

Binary $\rightarrow$ Hex (4-bit groups)

Partition bits into sets of $4$ from right to left (pad leading $0$s):

$$\underbrace{0010}_{2_{16}}\;\underbrace{1101}_{\text{D}_{16}} \implies 101101_2 = \mathbf{2\text{D}_{16}}$$

Part 5 • Specialized Binary & Character Coding

Weighted Codes, Non-Weighted Codes & Character Encoding Standards

Weighted Binary Codes

Fixed Positional Weights

Assigns a fixed numerical weight to each bit position so the value of each bit depends on its place:

8421 Code (BCD)

Weights: 8, 4, 2, 1

Also called Binary Coded Decimal; encodes each decimal digit separately using 4 bits.

2421 Code

Weights: 2, 4, 2, 1

Represents decimal digits and features self-complementing properties.

5211 Code

Weights: 5, 2, 1, 1

Weighted 4-bit code used for decimal digit representation.

BCD Conversion Walkthrough — Convert $59_{10}$ to BCD:

$$\text{Split digits: } 5 \rightarrow 0101_2, \quad 9 \rightarrow 1001_2 \implies 59_{10} = \mathbf{0101\;1001_{\text{BCD}}}$$

Non-Weighted Binary Codes

Rule-Defined Values

Does not assign fixed positional weights to bit positions; values follow specific encoding rules:

Excess-3 Code (Self-Complementary BCD Code)

Created by adding $3$ ($0011_2$) to the 8421 BCD value of each decimal digit (used for binary arithmetic correction).

$$\text{Convert } 5_{10}: \quad 5_{\text{BCD}} = 0101_2 \;\xrightarrow{+\,0011_2}\; 0101_2 + 0011_2 = \mathbf{1000_{\text{Excess-3}}}$$

Gray Code (Reflected Binary Code / Unit Distance Code)

Consecutive values differ by only one bit, minimizing transition errors in digital hardware where sudden multi-bit changes could cause false readings.

Binary $\leftrightarrow$ Gray Code XOR Conversion Rules

Shaft Encoders & ADCs

Binary $\rightarrow$ Gray ($10110_2 \to 11101_{\text{Gray}}$)

1. Keep MSB identical ($G_{\text{MSB}} = B_{\text{MSB}}$).
2. XOR each adjacent pair of binary bits ($G_i = B_{i+1} \oplus B_i$):

$$1 \;\; (1\oplus 0=1) \;\; (0\oplus 1=1) \;\; (1\oplus 1=0) \;\; (1\oplus 0=1) \implies \mathbf{11101_{\text{Gray}}}$$

Gray $\rightarrow$ Binary ($11011_{\text{Gray}} \to 10010_2$)

1. Keep MSB identical ($B_{\text{MSB}} = G_{\text{MSB}}$).
2. XOR each newly found binary bit with the next Gray bit ($B_i = B_{i+1} \oplus G_i$):

$$1 \;\; (1\oplus 1=0) \;\; (0\oplus 0=0) \;\; (0\oplus 1=1) \;\; (1\oplus 1=0) \implies \mathbf{10010_2}$$

Unpacked (Zoned) vs. Packed Decimal Formats ($\pm 789$)

Sign: + is 1100 (C), − is 1101 (D)

Unpacked (Zoned) Decimal (1 Byte/Digit)

Upper 4 bits = zone 1111 (F), except the least-significant byte whose upper 4 bits store the sign (1100 for $+$, 1101 for $-$):

$+789 = \mathbf{\text{F7 F8 C9}_{16}}$  |  $-789 = \mathbf{\text{F7 F8 D9}_{16}}$

Packed Decimal (2 Digits/Byte)

Eliminates wasted zone bits by packing 2 decimal digits per byte, placing the 4-bit sign in the rightmost nibble:

$+789 = \mathbf{78\;9\text{C}_{16}}$  |  $-789 = \mathbf{78\;9\text{D}_{16}}$

Instruction Set Architecture (ISA), Formats & Categories

The Instruction Set Architecture (ISA) acts as the contract between software and hardware—specifying the machine instructions a processor understands, how binary instructions are structured, where operands reside, and how the CPU executes programs step by step.

What the ISA Defines & How Abstraction Works

Five Core Specifications of an ISA

1. Instruction Set

The complete set of operations that the processor can perform.

2. Registers

Small, fast storage locations directly inside the CPU.

3. Data Types

Types of data values supported and processed by instructions.

4. Instruction Formats

Binary layout and structural arrangement of machine instructions.

5. Addressing Methods

Mechanisms used by instructions to locate operands in registers, memory, or constants.

ISA Abstraction in Action

Because the ISA shields programmers from physical circuit details, a developer can issue a single symbolic instruction while the processor orchestrates the underlying electronics:

Software Command: ADD R1, R2

Hidden hardware tasks handled automatically by the processor:

Control signals Data movement ALU hardware ops

Part 3 • Operands & Data Representation

Supported Processor Data Types & Operand Modes

Four Processor Data Types

Integer

Whole numbers without decimals ($10, -5, 25, 100, -10$). Used for counting, arithmetic operations, and index values.

Floating-Point

Numbers containing fractional decimal values ($3.14, 25.5$). Used for scientific calculations, engineering, and graphics.

Character

Single letters, digits, or symbols (A, B, %, 5) stored via ASCII or Unicode.

Boolean

Logical truth values ($\text{True} = 1$, $\text{False} = 0$) used in logical operations and decision-making.

Operand Categories (Where Data Comes From)

An operand is the data value or location operated on by an instruction (e.g., R1 and R2 in ADD R1, R2):

1. Immediate Operand ADD R1, 5

Constant value ($5$) is embedded directly inside the instruction itself.

2. Register Operand ADD R1, R2

Data is held inside a high-speed internal CPU register.

3. Memory & I/O Operands LOAD R1, Address

Memory Operand: Data resides in main memory and is accessed by memory address. I/O Operand: Retrieves or sends data to external peripherals (such as keyboards or printers).

Condition Code (CC) Register Flags & Subroutines

N • Z • V • C

Conditional branch instructions (such as BRANCH-IF-GREATER-THAN Loop) inspect individual status bits inside the Condition Code (CC) Register set by recent arithmetic or comparison operations:

Flag Name Condition to Set Flag = 1 (0 Otherwise)
Negative (N) Set to $1$ if the result of the most recent operation is negative.
Zero (Z) Set to $1$ if the result of the most recent operation is $0$.
Overflow (V) Set to $1$ if the most recent operation causes an arithmetic overflow.
Carry (C) Set to $1$ if the most recent operation results in a carry out.

How CALL & RETURN Use the Stack & Program Counter (PC):

• JUMP NEW-ADDRESS: Unconditionally overwrites the PC with NEW-ADDRESS (previous PC is lost).
• CALL SUBROUTINE: Pushes the incremented PC (address of the next sequential instruction) onto the stack, then loads the PC with the subroutine's starting address.
• RETURN: Pops the saved return address from the stack back into the PC, resuming execution right where the program branched.

Complete Processor Addressing Modes Reference (7 Modes)

An addressing mode is the method used by a machine instruction (via its mode field and address field) to specify where its operand or data can be found and how to compute the operand's effective memory address (EA).

Addressing Mode Where Operand / Address Field Points Memory Refs Advantages & Limitations
1. Immediate Addressing Operand value is included directly inside the instruction itself (defines constants or initial values). 0 refs
(beyond fetch)		 + Advantage: Fastest—no extra memory reference required.
− Limitation: Operand magnitude is restricted by the small bit width of the address field.
2. Direct Addressing Address field contains the actual effective memory address where the operand is stored in memory (e.g., Move P, R0). 1 memory ref + Advantage: Simple single memory read.
− Limitation: Provides a limited address space because the address field is shorter than a full word.
3. Indirect Addressing Address field specifies the address of a memory location that contains the full-length address of the operand ($\text{EA} = M[\text{Address}]$). 2 memory refs
(or more if cascaded)		 + Advantage: For word length $N$, expands addressable space to $2^N$.
− Limitation: Slower execution because fetching the operand requires two memory accesses.
4. Register Addressing Address field references a CPU register ($3\text{–}4\text{ bits}$ select among $8\text{–}16$ general-purpose registers) that holds the operand. 0 memory refs + Advantage: Very small address field needed in the instruction and rapid internal register access.
5. Register Indirect Addressing Address field refers to a CPU register that contains the effective memory address of the operand in main memory ($\text{EA} = [R_i]$). 1 memory ref + Advantage: Uses a compact register field while addressing memory using full register width (1 fewer memory access than memory-indirect).
6. Displacement Addressing Combines direct and register-indirect addressing: adds a direct address field $A$ to the contents of a register $R$ ($\text{EA} = A + [R]$). 1 memory ref Includes three sub-types: (1) Relative addressing, (2) Base register addressing, and (3) Indexing addressing.
7. Stack (Implicit) Addressing Implied addressing where operations automatically act on the top one or two elements of the LIFO stack pointed to by the Stack Pointer (SP). Part 6 • Program Traces & Stack Architecture

CPU Organizations, Stack (PUSH/POP) Mechanics & Evaluating $X = (A+B) \times (C+D)$

Based on the number of address fields, CPU organization is classified into (1) Single Accumulator organization, (2) General Register organization, and (3) Stack organization. Below is the complete trace of $X = (A+B) \times (C+D)$ across all instruction classes.

Register & Accumulator Traces for $X = (A+B) \times (C+D)$

1. Three-Address Program (3 steps)

ADD R1, A, B   ; R1 = M[A] + M[B]
ADD R2, C, D   ; R2 = M[C] + M[D]
MUL X, R1, R2  ; M[X] = R1 * R2

1.5-Address Variant: ADD B, R1 (one memory operand + one register operand).

2. Two-Address Program (6 steps)

MOV R1, A      ; R1 = M[A]
ADD R1, B      ; R1 = R1 + M[B]
MOV R2, C      ; R2 = M[C]
ADD R2, D      ; R2 = R2 + M[D]
MUL R1, R2     ; R1 = R1 * R2
MOV X, R1      ; M[X] = R1

3. One-Address (Single Accumulator $R_{\text{acc}}$) Program (7 steps)

LOAD A   ; Racc = M[A]
ADD B    ; Racc = Racc + M[B]
STORE T  ; M[T] = Racc
LOAD C   ; Racc = M[C]
ADD D    ; Racc = Racc + M[D]
MUL T    ; Racc = Racc * M[T]
STORE X  ; M[X] = Racc

Zero-Address Stack Architecture & Postfix (RPN) Trace

LIFO Stack & SP

A stack is a Last-In, First-Out (LIFO) structure managed by the Stack Pointer (SP) register. In a stack-oriented processor:
• PUSH places a new data item onto the top of the stack (stores value at SP and increments SP, e.g., $1023 \to 1024$).
• POP retrieves the top item from the stack into a register (decrements SP first, e.g., $1022 \to 1021$, and reads value).
• Arithmetic operations (like ADD or MUL) implicitly operate on the top two elements of the stack after converting infix expressions to Reverse Polish Notation (Postfix):

Infix: $X = (A+B) \times (C+D)$  $\longrightarrow$  Postfix (RPN): $X = AB+CD+\times$
